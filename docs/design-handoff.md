# 提示词画布 · 功能交接

给接手做界面设计的人看。这份只讲这个程序做什么、有哪些规则、数据长什么样、用户要完成什么事。界面怎么组织、怎么操作、长什么样，由你定，这里一概不提要求。

现在已经有一版能跑通全部功能的实现（怎么跑起来看最后一节），可以拿来理解功能，但它的布局和控件不是约束，可以全部推翻。

---

## 1. 这是什么，给谁用

一个人在自己电脑上打开的网页程序，用来写 MiniMax H3 的视频提示词。H3 是一个视频生成模型，它吃一大段结构化的文字提示词，外加最多 9 张参考图。

- **用户只有一个人**，就是这个程序的主人。没有登录、没有协作、没有权限，也没有别人能访问。
- **中文用户**，界面文字全中文。主力机器是 Windows。
- **他有两台机器**，靠同步盘共用同一个工作文件夹，所以同一份数据会在两台机器上轮流打开。
- **产出是文字，不是视频**。程序帮他写出提示词，他把提示词复制出去，按清单把图片传到第三方平台的网页上，在那边生成视频。这个程序自己不调用视频模型。

**核心诉求：反复试。** 同一个视频创意，他会换参考图、换说法、让 AI 一次给三个方向，再挑一个往下改，还要能回头对比早先那一版。所有功能都是围绕「多留几条路、随时回头」设计的。

## 2. 名词

请沿用这套叫法，这些词用户已经习惯了。

| 词 | 意思 |
| --- | --- |
| 画布 | 一个创作项目。比如「新年广告片」是一个画布。 |
| 节点 | 画布上的一段完整对话。一个画布里有多个节点，节点之间有父子关系。 |
| fork | 从某一条消息岔出一个新节点，把这条消息之前的对话复制过去，之后各走各的。用来比较不同写法。 |
| 消息 | 对话里的一句：用户说的，或 AI 回的。 |
| 版本 | 同一个位置上的另一条消息。改了用户那句话，或者让 AI 重答一次，就多一个版本，可以来回切换。 |
| 提示词框 | AI 回复里可以直接拿去用的那一整段提示词，程序会把它从回复里单独切出来。 |
| 方向 | AI 一次回复里给出的多个不同思路，每个方向一个提示词框，各带一句标签，比如「方向一：慢推近景，无台词」。 |
| 槽位 | 参考图的位置，每个节点 9 个，有编号，编号就是提示词里写的 `<Picture 1>` 到 `<Picture 9>`。 |
| 资产库 | 用户自己电脑上的图片文件夹，导入进来后可以浏览和搜索。图片不复制到别处，原地引用。 |
| 工作文件夹 | 所有画布、系统提示词、图片副本存放的地方，放在同步盘上。 |
| 上传清单 | 一份「这条提示词要传哪几个图片文件、按什么顺序」的名单，用户照着它去第三方平台传图。 |
| 拼图 | 把几张图拼成一张宫格大图，这样多张图只占一个槽位。 |
| 星标 | 给某一版提示词做的记号，意思是「这版效果好」。 |
| 系统提示词 | 给 AI 的长期指令，决定它按什么规矩写提示词。用户自己可以改，也可以存好几套。 |
| 模型配置 | 一组接口地址、密钥、模型名等，决定这个节点用哪个 AI。 |

## 3. 一次典型的使用

1. 新建一个画布，进去建一个节点。
2. 把电脑上放素材的文件夹导入资产库，挑几张参考图放进槽位，槽位自动有了 1、2、3 的编号。
3. 选视频时长（4 到 15 秒）和画面比例。
4. 用中文写需求发出去，比如「一个人在雨里走，最后停在灯下回头」。
5. AI 回一段话，其中包含一个或几个提示词框。每个框就是一条完整的、能直接用的提示词。
6. 觉得某个方向不错，就顺着它继续说「第二个方向再慢一点」；想同时保留两条路，就从那条消息 fork 出一个新节点，两边各改各的。
7. 中途换图、调顺序、改时长都可以，不用重新解释，下次发消息时程序会自动告诉 AI 变了什么。
8. 选定一版，给它打星，复制提示词，打开上传清单，照着名单把图传到第三方平台，生成视频。

## 4. 功能和规则

### 4.1 画布和节点

- 首页列出全部画布，能新建、重命名、删除。删除的进回收站目录，不是真删。
- 每个画布是一张可以自由摆放的图：节点散在上面，能拖动位置，父子节点之间有连线。
- 节点可以：新建（空节点）、fork（从任意一条消息岔出去）、重命名、折叠（把它下面所有子孙节点收起来，只说明收起了几个）、删除（连同它下面所有子孙节点一起删，删前要说清会删掉几个）。
- 有「自动排整齐」的功能：子节点排在父节点右边，兄弟节点上下排列。
- 节点标题由 AI 在第一次回复时自动起（不超过 12 个字），用户也能手动改；手动改过之后 AI 不再覆盖。

### 4.2 对话和版本

- 每个节点是一串对话，用户一句、AI 一句。
- 用户可以改自己之前说过的某一句，也可以让 AI 对同一句重新回答。这两种情况都不覆盖原来的，而是在同一个位置多出一个版本，用户能在几个版本之间来回切。
- 切到旧版本时，它后面的对话原样恢复；切回新版本，新版本后面的对话也还在。
- 改早先的一句话时，只改文字，那时候用的图片、时长、比例照旧。
- AI 回复是流式的，一个字一个字出来，中途可以叫停，已经出来的部分保留。
- 请求失败时这条消息标成失败，能重试。失败的消息不参与之后的对话。

### 4.3 提示词框

AI 的回复里，能直接拿去用的提示词被单独切出来，其余的解释、说明是普通文字。

一条提示词由六个部分组成，顺序固定，每部分以一个英文名字加冒号起头，描述文字是中文：

```
subject_definitions:   定义这条片子里出现的人、物、场景、风格，各自给一个标签
summary:               一段话概括这是什么任务、参考图起什么作用
retention_analysis:    逐条说明每个参考内容是照搬、是变形还是只做风格参考
detailed_description:  按播放顺序逐个镜头写画面、动作、运镜、声音、台词，这是主体，最长
overall_soundscape:    全片的环境声
non_diegetic_music:    配乐
```

提示词里会出现几种固定写法的标记，它们是内容的一部分，不能当成代码或标签处理，要原样显示：`<Picture 1>`（第几张参考图）、`<Subject 1>`（第几个角色或物件）、`[Shot 1] At 00:02.500`（第几个镜头、从第几秒开始）、`<d>[中文] 台词</d>`（台词）。

针对提示词框，用户要能做这几件事：

- **复制**整段提示词。
- **打星**，表示这版效果好。一个节点里只要有一版打了星，在画布上就该看得出来。
- **手动改**。用户可以直接编辑提示词的文字，改完存成一个新版本，不重新问 AI。
- **看上传清单**（见 4.7）。
- **沿这个方向继续**：等于从这条回复 fork 出一个新节点，并把「沿第 2 个方向（标签）往下改：」这句话预先填进输入框。

一次回复里可能有好几个方向，每个方向一个框，框上有一句标签说明。回复还在生成中时，没结束的框要能看出「还没写完」。

### 4.4 槽位和编号

- 每个节点有 9 个槽位，装参考图。编号就是位置，第 3 格就是 `<Picture 3>`。
- **中间不留空**：删掉第 2 张，原来的第 3 张自动变成第 2 张，提示词里的编号也跟着变意思。这一点会引起误解，用户得清楚哪张图现在是几号。
- 槽位能：放图、替换某一格的图、调顺序、删掉某一格。
- 图片有四种来源：资产库里的图；电脑文件夹里直接拿进来的图（不必先导入资产库）；拼好的宫格图；以及用户在写需求时临时引用的图（见 4.8）。
- 换图、调顺序、改时长比例，**不会立刻惊动 AI**，而是在下一次发消息时由程序自动附一句说明。说明的原话是固定的：
  - 第一次发：「参考图共 3 张，编号如下。视频时长 8 秒，画面比例 16:9。」
  - 只在末尾加了图：「新增参考图：`<Picture 4>`、`<Picture 5>`。」
  - 只换了某几张：「`<Picture 2>`、`<Picture 3>` 换成了下面的新图，其他不变。」
  - 删了图或调了顺序：「参考图已重新编号，以下是当前全部 3 张参考图，以此为准，之前的编号作废。」
  - 只改了时长或比例：「视频时长改为 12 秒。」「画面比例改为 9:16。」
- 这句自动说明是用户看得见的，它属于用户那条消息，但不是用户自己打的字。
- 每条发出去的消息都记着「当时槽位里是哪几张图」。所以切到旧版本时，槽位会跟着变回那时候的样子；如果当前有还没发出去的改动，切换前要提醒一次。

### 4.5 图片规则

H3 对图片有硬性要求，程序放图时自动处理，原文件不动：

- 每边 256 到 5760 像素，单张不超过 30 MB。太大的缩小，太小的放大，文件过大的重新压缩。
- 处理过的图会被记下来，用户要知道「这张图不是原图，传的时候要传处理过的那份」。
- 发给 AI 看的是另做的小图（长边默认 1600），用户不用管，但它影响费用。
- 支持 jpg、jpeg、png、webp。heic、heif、gif 不支持，在资产库里要能看出「这个用不了」。

### 4.6 资产库

- 用户导入自己电脑上的文件夹，程序只记路径，不搬文件。可以导入多个。
- 按文件夹浏览，也能按文件名搜索（搜全部导入过的文件夹）。
- 一个文件夹里可能有上千张图，需要缩略图和滚动加载。
- 能多选，一次把好几张放进槽位。
- 移除一个文件夹只是从库里去掉，不动用户的文件。

### 4.7 上传清单

用户要把提示词和图片拿到第三方平台去用，清单告诉他传哪几个文件、什么顺序。

- 按编号列出这条提示词对应的每张图：缩略图、编号、文件名、要传的那个文件在电脑上的完整路径。
- 如果这张图被程序处理过，或者原文件已经不在了，要说明该传的是程序存的那一份。
- 每一行要能「在资源管理器里显示这个文件」和「复制路径」。
- 提示词里引用了不存在的编号（只有 3 张图却写了 `<Picture 5>`），要醒目地提示。反过来，某张图提示词里压根没用到，也要标出来。

### 4.8 在需求里指某张图

用户写需求时经常要指名道姓：「把第二张图的衣服换成红色」。

- 写的过程中能挑一张图插进句子里，插进去的是一个跟着槽位走的引用，不是死编号。
- 挑的图可以是已经在槽位里的，也可以是资产库里还没进槽位的——后者会自动先放进下一个空槽位。
- 之后如果调了槽位顺序，句子里这个引用显示的编号要自动跟着变。
- 发出去的时候，它变成 `<Picture 2>` 这样的文字。
- 如果引用的那张图后来被从槽位里删了，这条消息发不出去，要说清是哪一处出了问题。
- 同样的引用能力，在用户手动修改提示词时也要有。

### 4.9 拼图

H3 只认 9 张图，不够用时用户把几张拼成一张。

- 行数列数各 1 到 3（1×1 不算拼图，不允许），格子是正方形，边长 1024 或 1536。
- 从资产库把图放进格子，格子之间可以互换位置，放错了可以覆盖。
- 图完整放进格子，长边贴边、短边居中，空的地方是白的。
- 可以选择给每格加编号（左上角一个数字）。不加编号时，用户会在提示词里用「左上」「第二排中间」这样的说法指某一格。
- 拼好存成一个 jpg 文件，存到用户指定的文件夹；如果那个文件夹在资产库里，库里要能马上看到它。

### 4.10 撤销

用户要求了标准的撤销和重做（Ctrl+Z / Ctrl+Shift+Z），最多回退 50 步。

- 能撤销的：节点移动、折叠、自动排整齐、删节点（连同子节点一起回来）、改名、槽位的各种改动、时长、比例。
- **不能撤销的：已经发出去的消息**。发出去就是发出去了，要改用版本切换。这是用户明确定的。
- 在写字的时候按 Ctrl+Z，撤销的应该是打的字，不是画布。
- 换一个画布，撤销记录重新开始。

### 4.11 设置

用户第一次打开程序时什么都还没有，必须先设置才能用：

1. **工作文件夹**：选一个目录，建议放同步盘。设好后程序在里面建好目录结构，并放进三套自带的系统提示词。
2. **模型配置**：可以存多套。每套包括名字、接口地址、密钥、模型名、发给模型的图片长边，以及可选的价格（币种、输入价、输出价、缓存命中价，按每百万 tokens 填）。能测试连接是否通。
3. **系统提示词**：列出全部，可以直接改、新建、删除、用外部编辑器打开。自带三套：`ref2va`（有参考图，新节点默认用它）、`i2v`（一张图当第一帧往后演）、`t2v`（纯文字，不用图）。
4. 程序固定附加在每套提示词后面的一段格式要求，只能看不能改。

每个节点各自选用哪套模型配置、哪套系统提示词。

### 4.12 等待和出错

这些状态用户会经常碰到，都要有交代：

- AI 正在回复（逐字出现，可以中途叫停）。
- 请求失败（要能看到失败原因，并能重试）。
- 图片正在放进槽位（大图要处理几秒）。
- 槽位满了、图片格式不支持、尺寸不达标、引用的图已经不在了、路径不让访问。
- 保存是自动的，没有「保存」这一说，但改动确实写进了文件。

## 5. 数据规模

- 画布：几个到几十个。
- 一个画布里的节点：常见 2 到 10 个，多的可能上二三十。
- 一个节点里的消息：常见十几条，长对话可能几十条。
- 一条 AI 回复：几百到两三千字，其中提示词部分占大头，`detailed_description` 一段就可能上千字。
- 槽位：固定 9 个。
- 资产库单个文件夹：可能上千张图。
- 一次请求的费用量级：几分钱到几毛钱，用户想随手看到。

## 6. 每样东西要能看出什么

不是要求怎么显示，是说这些信息用户需要，缺了会出问题。

- **画布列表里的一个画布**：标题、有几个节点、什么时候动过。
- **画布上的一个节点**：标题、里面最新那版提示词讲的是什么（一句话概括）、槽位里现在是哪几张图、有没有打过星、这次回复给了几个方向、折叠时藏了几个子节点、现在是不是正在生成。
- **一条用户消息**：他打的字、程序自动附的那句说明、这次带了哪几张图（带编号）。
- **一条 AI 消息**：框外的解释、每个提示词框和它的方向标签、这条在同一位置有几个版本、现在是第几个、用的哪个模型和哪套系统提示词（而且要能查到当时那套提示词的原文）、花了多少 token 和多少钱。
- **一个槽位**：第几号、是哪张图、这张图有没有被程序处理过。
- **资产库里的一张图**：缩略图、文件名、支不支持、有没有被选中。

## 7. 运行环境和限制

- 本机跑一个服务，浏览器打开，只监听本机，同一局域网的人也连不上。不打包成桌面程序。
- 单人使用，没有账号体系，任何界面上都不需要出现「谁」。
- 界面文字全中文。
- 主力是 Windows，浏览器是 Chrome 或 Edge，桌面显示器。
- 密钥、导入过哪些文件夹、这些只存在本机；画布、图片副本、系统提示词、模型配置（不含密钥）存在同步盘的工作文件夹里，两台机器共用。
- 已知风险：两台机器同时开同一个画布，同步盘可能产生冲突副本。

## 8. 以后可能加的

现在不做，但设计上最好别堵死：

- 在提示词框上直接发起视频生成，生成结果挂回这条提示词下面（数据结构已经留好位置）。
- 视频和音频参考素材，各 3 个位置，编号和图片各自独立（`<Video 1>`、`<Audio 1>`）。
- 复制提示词时，按目标平台的写法自动改写 `<Picture N>`。
- 两个节点的提示词并排对比、按内容搜节点、按画面内容搜图。

## 9. 怎么把现在这版跑起来看

需要 Node 24。

```bash
npm install
npm start
```

浏览器会自动打开。第一次进去会要求先设工作文件夹（随便选个空目录）和模型配置。

**不想花钱调真模型**，就另开一个终端跑假模型：

```bash
npm run mock-llm
```

然后在设置里把接口地址填 `http://127.0.0.1:3799/v1`，模型名随便填，密钥随便填。这个假模型会返回结构完整的假回复，全部功能都能点通。

更细的东西在这两份文档里：需求是怎么定的、为什么这么定，看 `docs/requirements-interview.md`；每条规则的具体做法，看 `docs/dev-plan.md`。
