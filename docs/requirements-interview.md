# 提示词画布 需求访谈记录

访谈于 2026-09-15 完成。开发计划在 `docs/dev-plan.md`，默认系统提示词草稿在 `docs/prompts/default.md`，程序固定附加的格式要求在 `docs/prompts/format-requirement.md`。这份记录讲「为什么这么定」，计划讲「怎么做」。

## 一句话说明

一个本机运行的画布：往最多 9 个图片槽位里放参考图，和 agent 对话，让它写给 MiniMax H3 用的视频提示词。一个对话是一个节点，可以从任意一条消息 fork 出新节点。资产库导入本机文件夹，快速把图放进槽位。

## 已经定下的

### 目标和范围

1. **目标视频模型只做 MiniMax H3。** 提示词里引用图片用 H3 官方写法 `<Picture N>`。原因：一个模型的写法吃透，比同时照顾几个效果好；官方写作指南可以直接当 agent 的底子。
2. 第一版只出提示词，不在画布里生成视频。以后会接第三方接口调用 H3，现在先预留：每条给出提示词的回复旁边留位置，以后挂生成的视频；提示词和当时槽位里的图、时长、比例绑在一起存，接接口时直接拿去用。
3. 参考素材第一版只做图片，最多 9 张，编号 `<Picture 1>` 到 `<Picture 9>`。视频和音频参考以后再加：H3 的图片、视频、音频各自单独从 1 开始编号（`<Video 1>`、`<Audio 1>`），以后加上也不影响现有的图片编号。
4. 只有自己用，在本机运行，用浏览器打开本机页面。每个画布存成一个文件夹，可以放在同步盘里，两台机器都能打开。
5. 第一版生成的提示词，贴到以后要接接口的那个第三方平台的网页版上去生成视频。原因：复制出去的写法和以后接口调用时一致，接接口时不用改。

### 槽位

6. 槽位跟着每条消息走。每个节点有自己的 9 个槽位；每条消息记下发出时槽位里是哪几张图（只是一条记录，不会重新上传图片）；从哪条消息 fork，新节点就带上那时候的图。
7. 槽位中间不留空。删掉中间某张图，后面的图自动往前补，不然上传时编号会对不上。
8. 替换某张图的操作：
   - 把资产库里的新图拖到对应槽位上，或者点槽位再从资产库里选，直接替换，编号不变。
   - 换完不会马上发给 agent，可以一次换好几张。
   - 发下一句话时，程序自动在这条消息里带上新图，并注明哪个编号换成了新图。
   - 换图之前的消息和提示词，旁边仍显示旧图。
   - 想把换图前后两个版本都留着对比，就先 fork 出新节点，再在新节点里换。
9. 追问、改细节时不用重新传图。图片只在第一次放进槽位或换图时加进对话，之后一直留在对话记录里，agent 都看得到。

### 对话、fork 和版本

10. 从你的某句话 fork：这句话放进新节点的输入框，让你改了再发。从 agent 的某条回复 fork：新节点接着这条回复往下聊。
11. 想改前面某句话，或重新生成某条回复时，在原节点里改。改完生成一个新版本，旧版本保留，像 ChatGPT 那样可以来回切换（显示“1/2”），旧版本里的回复和后面的对话都在。
12. 可以直接手动修改 agent 写好的提示词。改完算这条回复的一个新版本，可以切回原版。之后 agent 看到的、卡片上显示的、复制出去的，都是改过的那版。

### 画布

13. 节点卡片显示：标题（agent 按内容自动起，可以改）、槽位缩略图、最新提示词里的概述（`summary`）那一段、星标。
    - 星标用来记“这版效果好”，因为第一版的视频在别处生成，回来得有地方记下来。
    - 原来定的是“最新提示词开头两行”，后来改成概述：按官方格式，提示词开头是主体定义，看不出这条视频讲什么。你没有反对。
    - 第 22 条的一条回复里有多个提示词框时，显示第一个框的概述，并标出一共有几个方向。

### agent

14. 大模型接口用 OpenAI 兼容格式，接口地址、key、模型名在设置里填，可以换不同的大模型。图片在后面几轮对话里会不会按缓存价计费，取决于具体服务商。
15. 模型和系统提示词每个节点单独选。
    - 设置里可以存多套系统提示词，每套是一个文件，在编辑器里也能改。
    - 节点选用的模型和系统提示词，fork 时带到新节点，也可以换。同一个需求 fork 出两个节点，就能对比不同模型或不同写法的效果。
    - 改了某套系统提示词后，从下一条回复开始按新版写。每条回复都记着当时用的模型和系统提示词版本。
16. 程序在系统提示词后面固定加一小段格式要求，让 agent 把提示词放在单独的提示词框里，程序按框取出，用于节点卡片、一键复制和以后发给 H3。这段格式要求的原文在设置里能看到。
17. 时长（4 到 15 秒，整数）和画面比例放在槽位旁边，跟着每条消息记录，程序会自动告诉 agent，fork 时一起带到新节点。清晰度不影响提示词怎么写，等接接口时再加。

### 资产库

18. 导入文件夹时原地引用：只记下路径、生成缩略图，文件夹里新加的图会自动出现。某张图一放进槽位，就复制一份到画布文件夹里；之后原图被移走、删掉，或者在另一台机器上打开画布，节点里的图都还在。
19. 在输入框和提示词里输入 @ 时：
    - 弹出的列表先显示当前槽位里的图，下面还能搜整个资产库。
    - 选槽位里的图，插入 `<Picture N>`；选资产库里的图，程序把它放进下一个空槽位，再插入对应编号。
    - 插入后显示成带缩略图的小标签，调整槽位顺序时，标签上的编号跟着变。
20. 资产库按文件夹浏览、按文件名搜。按画面内容搜以后不够用再加。

### 复制和上传

21. 复制提示词去网页上用时，画布里显示一个上传清单：按编号列出大图和原文件位置，你照着去原文件夹找图、按顺序上传。原文件找不到时（比如在另一台机器上），显示画布文件夹里存的那份的位置。

### 一次出多个方向

22. 让 agent 一次出几个不同方向时，放在同一条回复里，每个方向一个提示词框。
    - 每个框旁边有按钮，点了就从这条回复 fork 出新节点，输入框里预先填好“沿第 N 个方向往下改”。
    - 节点卡片显示第一个框的概述，并标出一共有几个方向。
    - 每个框各有自己的复制按钮；以后接接口时，也是对某一个框单独发起生成。

### 换一批图套用同一套写法

23. 不专门做功能，用现有操作：从出了好提示词的那条回复 fork，在新节点里换图，再发一句“按新图改写这版”。

### 拼图

24. 要做拼图功能：把几张图拼成一张 4 宫格、6 宫格、9 宫格等的大图，只占一个槽位。原来问的“把几张图存成一组，一次放进槽位”不做。
    - 在资产库里拼，拼好就是一张普通图片，之后和普通图片一样用；想改其中一格就整张重拼。
    - 行数和列数各选 1 到 3，4、6、9 宫格和 1×2、1×3 都能拼；在格子之间拖动可以调顺序。
    - 每次拼完问存到哪个文件夹，记住上一次选的。
    - 原图比例和格子不一样时，整张图完整放进格子，空出来的地方补白色底。
    - 格子编号可选：勾上后每格左上角加一个小号数字，默认不勾，因为数字有可能被 H3 生成进视频里。不加编号时，提示词里用“左上”“第二排中间”这类说法来指某一格。
    - 拼好的图每边不超过 5760 像素，符合 H3 对参考图的要求。
    - 风险：H3 会不会把整张宫格图当成一个画面去生成，要试过才知道。

### 界面布局

25. 点开节点时，对话显示在右侧面板；画布在中间，边聊边能看到整棵树，点别的节点面板直接切过去。槽位、时长和比例放在面板里输入框的上方。资产库放在最左边，可以收起来。

### 默认系统提示词和提示词语言

26. 我照着 H3 官方写作指南起草一份中文的默认系统提示词，你再改。官方指南有两份：参考模式（ref）和基础写法（base），参考模式那份引用了基础那份的镜头、台词写法，两份都要用上。
27. 提示词直接用中文写。你已知道这不符合官方格式，生成效果可能打折扣。具体做法：
    - 六个部分的名字（`subject_definitions` 等），以及 `<Subject N>`、`<Picture N>`、`[Shot N] At MM:SS.mmm`、`(S1)`、`<d>[语言] ...</d>` 这些标记，照官方原样保留，只有描述文字用中文，这样和官方格式差得最少。
    - 以后想对比英文的效果，另存一套英文的系统提示词，fork 出两个节点对比。

### 画布操作

28. 第一版做这三项：
    - 删除节点，连同从它 fork 出去的子节点一起删。
    - 折叠分支，把子节点收起来，只显示有几个。
    - 节点可以随意拖动，另外有一个“自动排整齐”按钮。
    - 两个节点的提示词并排对比、按标题和内容搜索节点，等节点多了再加。

### 画布怎么存

29. 设一个工作文件夹，所有画布都是它下面的子文件夹。
    - 首页列出全部画布，新建画布就建在工作文件夹里。
    - 工作文件夹放在同步盘上，另一台机器设成同一个位置，就能看到全部画布。
    - 所有改动自动保存，不用手动点保存。
    - Ctrl+Z 可以撤销画布上的操作和槽位改动；已经发出去的消息不能撤销，要改就用版本切换。
    - 系统提示词放在工作文件夹里，两台机器共用。接口 key 和资产库导入了哪些文件夹，只存在本机：两台机器的路径可能不同，key 也不适合放在同步盘上。
    - 风险：两台机器同时打开同一个画布，同步盘可能生成冲突副本。

### 星标

30. 星标打在具体的提示词框上；卡片上只要有一个框打了星，就显示星标。原因：一个节点里有多个版本、多个方向，得知道具体是哪一版效果好。

### 图片尺寸

31. 槽位里的图超出 H3 要求（每边 256 到 5760 像素、每张不超过 30 MB）时，放进槽位的那一刻，画布文件夹里存的那份自动处理到要求以内：太大的缩小，太小的放大到短边 256 像素，文件太大的重新压缩。原图不动。上传清单里，这张图指向处理过的那份。

### 复制出去的写法

32. 以后调用 H3 的第三方平台还没定。复制时先原样用官方写法 `<Picture N>`。平台定了再查它的写法，不一样就在复制时自动转换。

### 程序怎么跑

33. 本机起一个 Node 服务，浏览器打开。这台机器已有 Node 24。导入文件夹时弹出系统的选文件夹窗口。不打包，另一台机器装 Node 就能跑。

### agent 遇到说不清的需求

34. 先按它的理解写一版，并在提示词框外面说明它假设了什么，不满意再改。这条写进默认系统提示词。

### 第一版范围（已确认）

先做，跑通主流程：

- 首页、工作文件夹、新建和打开画布、自动保存
- 画布：节点卡片、fork、右侧对话面板、消息版本切换、删除、折叠、拖动和自动排整齐
- 槽位：9 个、跟着消息记录、替换、调顺序、自动补位、存进画布文件夹并按 H3 要求处理尺寸
- 资产库：导入文件夹、按文件夹浏览、按文件名搜、双击和多选拖入
- agent：OpenAI 兼容接口、多套模型配置、每节点选模型和系统提示词、格式要求、标题、时长和比例、默认中文系统提示词
- 提示词框：复制、星标、手动修改、一条回复多个方向、上传清单

接着做，第一版收尾：

- 输入 @ 选图
- 拼图
- Ctrl+Z

以后再说：

- 接第三方接口调用 H3，视频挂回提示词框
- 视频和音频参考槽位
- 按画面内容搜图
- 两个节点提示词并排对比、搜索节点
- 清晰度设置
- 复制时按平台写法自动转换 `<Picture N>`

### 按常规做的细节（没单独问你，不对就说）

- 发给 agent 时，每张图前面标一行“`<Picture N>`”，agent 才知道哪张是几号。给 agent 看的图另外缩到长边 1600 像素左右，省钱，不影响它看清内容；上传清单用的仍是第 31 条处理过的那份。
- 节点标题：让 agent 在给出提示词时顺带给一个标题（写进第 16 条那段格式要求里），不另外多调一次模型。fork 出的新节点先沿用父节点的标题，agent 第一次回复后再改。
- 设置里可以存多套模型配置（名字、接口地址、key、模型名），节点从里面选一套。
- 输入框 Enter 发送，Shift+Enter 换行。回复逐字流式显示。
- 时长、比例中途改了，和换图一样，下一条消息里自动注明。
- 界面全中文。

### 放图的基本操作（按常规做）

- 双击资产库里的图，放进下一个空槽位。
- 按住 Ctrl 选中几张图一起拖进来，按选中的先后顺序填进槽位。
- 在槽位之间拖动图片可以调顺序。

## 查到的 H3 限制

这些是资料里查到的，不是我们定的。

- 参考素材：图片最多 9 张；视频最多 3 段，每段 2 到 15 秒，合计不超过 15 秒；音频最多 3 段，每段 2 到 15 秒，不能单独用，必须搭配图片或视频；三类加起来最多 12 个文件。
- 参考图片（官方文档）：宽和高都在 256 到 5760 像素之间；格式 JPG、JPEG、PNG、WEBP、HEIC、HEIF；每张不超过 30 MB。视频每段不超过 50 MB，音频每段不超过 15 MB。
- 生成的视频：官方文档写 4 到 15 秒、只能是整数（有第三方平台写 5 到 15 秒，以官方为准）；清晰度 768P 或 2K；每秒 24 帧，自带立体声。画面比例有 21:9、16:9、4:3、1:1、3:4、9:16 和自动。
- 参考图清晰度：有第三方指南建议主体用 1080p 左右的清晰正面图，图太糊会影响人物前后一致。
- 提示词最长约 7000 字符（第三方平台文档的说法）。
- 能用的地方：海螺 App 和网页、MiniMax Hub 桌面版、MiniMax 开放平台接口，以及第三方平台。

## H3 官方参考模式写作指南的要点

读的是原文 `VIDEO_PROMPT_WRITING_GUIDE_ref_en.md`（约 2.3 万字符）。同目录还有 `VIDEO_PROMPT_WRITING_GUIDE_base_en.md`（基础写法）和一份许可证问答，没有中文版。这台机器能直接访问 Hugging Face。

- 提示词要全部用英文写，只有台词、歌词和画面里出现的文字保留原语言。
- 提示词分六个固定部分，按顺序：`subject_definitions`（主体定义）、`summary`（概述，开头带任务类型，比如 `[reference generation]`）、`retention_analysis`（每个参考内容保留多少）、`detailed_description`（按镜头写画面、动作、运镜、声音、台词）、`overall_soundscape`（环境声）、`non_diegetic_music`（只有观众听得到的配乐）。
- 引用标签有四种：
  - `<Subject N>`：从参考素材里提炼出来、要在视频里用的内容，比如人物、场景、服装、风格。一个主体可以来自好几张图，一张图也可以提供好几个主体。
  - `<Picture N>`：只有图本身当作某个镜头的首帧、关键帧、尾帧、构图参考或分镜参考时，才单独写。图只用来定人物、场景、服装时，写成“`<Subject 1>` 是 `<Picture 1>` 里的女生”，不单列。
  - `<Video N>`、`<Audio N>`：视频和音频参考，和图片各自单独编号。
- 分镜参考图有正式写法：说明这张图对应哪几个镜头、提供了哪些规划信息（视角、主体位置、镜头顺序）。宫格图可以按这个用。
- 镜头写法：`[Shot 1]` 不带时间；后面的镜头写 `[Shot N] At MM:SS.mmm, ...` 标出切镜时间。所以 agent 必须知道视频时长。
- 台词写法：说话人用 `(S1)`、`(S2)` 编号，台词写成 `<d>[语言] ...</d>`。H3 自带声音，提示词里要写台词、环境声和配乐。
- 长度：生成类任务的 `detailed_description` 一般 350 到 500 个英文单词，台词多时以放下完整台词为准。

对前面决定的影响：

- 第 19 条的 @ 小标签、第 6 到 8 条的换图和调顺序，只对应 `<Picture N>`。`<Subject N>` 是 agent 自己定义的，不对应槽位，调槽位顺序时不能动它的编号。
- 第 13 条节点卡片改成显示 `summary` 那一段。
- 第 27 条：你选了提示词直接用中文写，和指南要求的英文不一致，标记保留原样。
- 第 17 条的时长必须告诉 agent，因为切镜时间要按时长写。
