# 提示词画布 · 功能需求重设计

版本：2026-10-13，需求草案。核对基线：`main` 的 `b51db72`。

用途：给后续设计和开发提供一份一致的功能口径，重点整理最近合入的图像编辑、Krea2、SelfLift 和任务管理能力，同时保留原有创作、素材和版本能力。

范围：功能目标、输入输出、业务规则、数据关系、异常结果、验收标准。本文件不规定页面布局、视觉样式、控件、导航、操作手势或用户交互流程。文中的功能分组是业务分类，不对应页面分区。

本文件仍区分已确认规则与建议，不能把全部建议视为已交付。2026-10-13 用户确认更新后的画布原型并授权功能接入；本轮实现范围、兼容选择和验证记录见 [原型功能接入报告](reports/prototype-integration-20261013.md)。旧图像编辑原型已按用户要求移除，其他 agent 的草稿保留。

## 1. 产品目标与整理结论

产品现在是一个本机运行的图像与视频创作工具：把素材、创作要求、提示词、生成参数和结果保存在同一个项目中，支持不断试验、比较版本、派生新结果和回到早期方案。

核心业务链为：**素材与要求 → 可执行提示词 → 生成任务 → 图像或视频结果 → 保存、比较、继续创作**。其中，提示词编写和媒体生成可以独立使用；已有提示词或无需提示词的操作，不必经过一次聊天模型调用。

本次重新整理采用以下口径：

1. **以创作目的定义功能。** 文生图、转真人、换装、局部重绘、四视图等各有明确目标；模型、LoRA、工作流是完成目标的执行条件。
2. **分清三个层次。** 创作要求说明想要什么；执行提示词说明模型如何生成；任务快照记录这次实际用了什么。三者分别保留。
3. **同一能力采用同一业务定义。** 四视图、放大等可以处理不同来源的图片，输入规则、参数含义和结果归属保持一致。现有多个调用来源不构成多个独立功能。
4. **原素材、预览、最终结果和派生版本分别记录。** 生成失败或结果不满意时，原素材和历史版本仍可使用。
5. **按实际执行状态管理任务。** 完成状态、预览可用性、文件是否仍存在是不同信息，分别判断。
6. **功能正确性与模型效果分开验收。** 接线正确、参数生效、任务完成是程序验收；身份、服装、姿势、接缝和美感还需看实际输出。

这些整理不要求重建画布、增加节点类型或改写现有存储格式。

## 3. 业务对象与归属

### 3.1 对象定义

| 对象 | 负责保存什么 | 与其他对象的关系 |
| --- | --- | --- |
| 画布 / 创作项目 | 标题、节点关系、项目内素材副本 | 一个项目含多条创作分支 |
| 创作节点 | 一段对话、用途、当前素材、当前默认参数 | 保留现有 `image`、`edit`、`video` 三种用途；建立后用途不变 |
| 素材 | 图片、视频、音频及其来源、尺寸或时长 | 本机资产可被不同项目使用；进入项目后保存可持续引用的副本 |
| 消息及版本 | 用户要求、模型回复、当时素材与创作条件 | 修改与重答保留旧版本；fork 复制对应位置的上下文 |
| 提示词候选 | 可独立执行的文字、所属消息、候选序号、来源用途 | 一次回复可有多个候选，每个候选可对应多次生成 |
| 生成任务 | 本次输入、参数快照、随机种子、执行标识、状态及错误 | 归属于具体项目、节点和候选；生成一组图片时另记录每张状态 |
| 生成结果 | 本地文件、尺寸 / 时长、保存位置、源任务 | 预览、完整结果、停止后保留的部分结果各有含义 |
| 派生关系 | 从哪张图、哪条视频或哪个版本继续生成 | 放大、重绘、四视图、重拍、接续重出均保留源结果 |
| 执行配置 | 聊天模型配置、ComfyUI 目标、模型文件、工作流与预设 | 配置提供新任务的默认值；已提交任务保留自己的执行快照 |

**实现基线：** 节点类型与系统提示词用途匹配；生图节点可以切换 IL、Pony、Krea2 系列；fork 保留原节点用途。历史缺少类型的节点按已有兼容规则读取。

**本次建议：** 后续需求和设计统一使用以上对象关系，避免把“提示词版本”“生成任务”“生成结果版本”都统称为一个版本。此处不新增数据库或强制迁移旧数据。

### 3.2 三种“文字”

| 文字 | 作用 | 必须保留的区别 |
| --- | --- | --- |
| 创作要求 | 用户希望改变的内容、约束和参考用途 | 可以是中文，不保证直接适合生成模型 |
| 执行提示词 | 实际进入生成工作流的内容 | 按系列 / 操作决定是标签、画面描述、编辑指令或固定主指令加补充要求 |
| 模型辅助文字 | 翻译、优化、图像反推等产生的内容 | 记录来源；辅助生成与媒体生成是不同任务阶段 |

用户自行提供可执行文字时，仍能保存和生成。放大无需生成执行提示词；四视图无需额外要求；转真人开启反推时无需手输提示词。

补充业务约束：

- 消息记录当时的参考素材、时长和比例；旧提示词的素材含义不随当前素材改动而重写。
- 素材变化在下一次创作请求中形成说明；图片重新编号后，模型按本次编号解释。
- 稳定素材引用在发送时转换为 `<Picture N>` 等执行标记；被移除的引用不能被误解释为另一个素材。
- 截断对话只影响下一次请求，不删除历史；保留起点补上当时的参考图，并记录保留 / 截断轮数。默认全带，可选全部、5、10、20、30、50 轮。
- 已发送消息通过版本机制管理；本地未提交改动使用撤销 / 重做。两类历史分别保存。
- 系统提示词修改从后续回复生效；每条回复记录所用模型与提示词版本。
- 模型返回的 token 用量、缓存用量与配置单价用于记录回复费用；估算值与真实服务商账单分别理解。媒体任务耗时、云实例运行成本与聊天费用含义不同。

## 5. 素材与资产能力

### 5.1 素材来源、读取与保存

**已确认 / 实现基线：**

- 资产库支持多个本机文件夹，原地引用，不移动原文件；移除库目录不删除用户文件。
- 图片、视频、音频都可作为资产；按文件夹、文件名查询，按修改时间或文件名正反排序，默认修改时间较新在前。
- 图片完整文件、缩略图、模型阅读用缩小图分别使用。查看和后续编辑必须能读取完整图片；缩略图不替代生成输入。
- 图片进入画布后保存副本；重复内容去重，只有新增图片占用新的参考位置。
- 生成结果先存临时目录，由用户决定保存到长期目录；程序不自动清理。文件被清理后保留任务参数，文件缺失与生成失败分别记录。
- 已保存的生成图片可进入资产库及视频参考；临时生成图片沿用现有保存后复用规则。
- 原文件缺失时，项目副本仍可参与创作；外部上传清单记录每个编号实际应使用的文件及路径。

### 5.2 输入约束

| 素材类型 | 当前约束 | 状态 |
| --- | --- | --- |
| 图片参考 | 每节点最多 9 张；编号连续；jpg、jpeg、png、webp | 已确认 |
| H3 图片处理 | 每边 256–5760 像素、单张不超过 30 MB；处理副本，原文件不改 | 已确认 |
| 视频素材 | mp4、mov、webm、m4v；作为普通参考时需要当前浏览器可解码 | 实现基线 |
| 音频素材 | mp3、wav、m4a、aac、ogg、flac | 实现基线 |
| 拼图 | 行列各 1–3，不允许 1×1；格边 1024 或 1536；完整保留单图、空白补白；可记录格子编号，输出 jpg | 已确认 |

SelfLift 续写起点另走服务器探测和规整流程，不能把普通视频参考的浏览器解码限制直接套用在续写输入上。

## 6. 图像功能重新归类

### 6.1 从文字生成图片

| 能力 | 目的与输入 | 执行契约 | 状态 |
| --- | --- | --- | --- |
| IL / Pony 文生图 | 标签描述生成角色或场景 | 按系列补固定开头与默认负面词；支持底模、LoRA、尺寸、张数、种子与采样参数 | 已确认 |
| Krea2 文生图 | 英文自然语言描述生成图片 | Turbo 路线；独立模型、文字理解、LoRA、尺寸与采样参数；不套用 Danbooru 标签校验 | 已确认 |
| 参考图生图 | 参考图片结合文字生成新图 | 当前 IL/Pony 图生图与 ControlNet、Krea2 图像参考各按已实现契约执行 | 已确认 / 实现基线 |
| 导入工作流 | 使用已有 ComfyUI API 工作流 | 只替换已声明映射的正负提示词、种子、宽高；其他模型和采样参数由原工作流决定 | 已确认 |

文生图一组支持 1–8 张，逐张执行及记录状态。IL/Pony 的高级链包括放大 / 高清修复、部位重绘、多个 ControlNet；实际使用前校验该环境中的模型、预处理器与节点。

**本次建议：** 用“生成目标 + 输入契约”解释功能，模型系列作为执行条件。Krea2 系列与“转真人操作”分别定义，不能因为同属 Krea2 就共享所有提示词与参数。

### 6.2 从已有图片派生结果

以下八项为当前图像编辑能力。表中的内容是业务定义，不限定从哪里发起。

| 编号 / 功能 | 必要输入 | 改变目标与保留目标 | 文字契约与输出规则 |
| --- | --- | --- | --- |
| I01 指令编辑 | 原图 + 编辑指令 | 按要求改内容，尽量保留未要求改变的主体和环境 | 编辑指令；走当前 Krea2 编辑工作流 |
| I02 转真人 | 原图；双图时另有真人参考 | 图 1 提供构图 / 姿势，图 2 提供人物外观参考；生成真人风格 | 手输或反推；遵循标准工作流，长边 1536，见第 7 节 |
| I03 换装 | 原图 + 服装要求 | 改服装，尽量保留身份、姿势与其他内容 | 服装编辑指令；使用换装工作流 / LoRA |
| I04 局部重绘 | 原图 + 有效掩码 + 区域内容要求 | 重画指定区域，保留遮罩及羽化范围以外的像素 | 描述该区域应画成什么；走现有 SDXL 裁切、重绘、拼回流程 |
| I05 深度迁移 | 原图 + 新画面描述 | 沿用深度结构、构图与透视，重新生成画面内容 | 整张画面描述；当前输出固定 1024×1024，控制强度必须大于 0 |
| I06 风格 Remix | 原图 + 新画面描述 + 对应 LoRA | 按当前 ReID / RealCosplay 变体重构人物或场景风格 | 新画面描述；当前输出固定 1024×1024，不承诺精确换脸 |
| I07 放大 / 高清 | 原图 + 放大倍率 / 模型 | 增加分辨率，可选面部修复；原图保留 | 无需聊天模型写词；编辑节点的基础放大重绘强度固定 0，面部修复另计 |
| I08 四视图 | 角色图，可有补充要求 | 脸部特写、正面 / 侧面 / 背面全身组成角色设定图 | 固定主指令 + 额外要求；默认 1536×1024 |

**实现基线：** 上述八项均已落地；放大可有不同处理链。生图阶段的高清修复可以附带重绘，编辑节点的基础放大是只放大，再按需做面部修复。两者的重绘含义须分别记录。

**已确认：** 四视图可以使用 IL、Pony、Krea2 生成的图片，也可使用参考素材。框中文字作为额外要求追加到固定四视图指令；常用尺寸预设与自定义宽高保留。编辑结果调用四视图继续挂在源候选下，不改变节点当前的编辑用途。

**本次建议：** 换装保留为约束明确的专用操作；指令编辑处理一般修改。深度迁移强调结构参考，Remix 强调重构，转真人强调真人化。三者不能统称为“换风格”，也不能把真人参考强度解释为身份相似度的保证。

### 6.3 参数归属

| 参数层 | 负责什么 | 生效范围 |
| --- | --- | --- |
| 全局 / 系列默认值 | 新创作的初始模型与参数 | 尚未覆盖默认值的新请求 |
| 节点当前设置 | 此分支接下来采用的默认配置 | 新任务创建时读取 |
| 操作专属输入 | 原图角色、图 2、掩码、提示词、强度及操作变体 | 当前操作请求；局部覆盖不能把其余设置重置为默认 |
| 工作流契约 | 支持的参数、固定接线、必要模型、实际尺寸算法 | 对应操作；通用宽高和采样设置未必生效 |
| 任务快照 | 最终提示词、素材引用、种子、工作流标识和实际参数 | 当前任务及按原参数重出 |

**实现基线：** 转真人不接受通用宽高改变实际尺寸；深度迁移 / Remix 固定 1024×1024。实际尺寸必须根据所选操作记录，不能仅复用节点的通用宽高。

编辑候选已通过所属消息的素材快照解析原图身份。素材重新排序后仍对应原图；直接执行候选时，原图已不在当前参考素材中会被拒绝。复用候选文字到当前编辑设置时另遵循现有素材替换规则，不要求再增加一份素材绑定字段。

**本次建议：** 后续设计和开发统一说明参数适用范围。只有真正进入该工作流的参数才算本次执行参数；同参数重出沿用原任务快照，修改后的节点默认值用于新的创作。

## 7. 转真人专项需求

### 7.1 四组合

| 模式 | 图像输入 | 提示词来源 | 验收重点 |
| --- | --- | --- | --- |
| 手输单图 | 图 1 | 手输完整提示词，或简短要求补主触发词 | 手输内容进入生成分支，不调用反推 |
| 手输双图 | 图 1 + 图 2 | 手输，使用双图语义 | 图 2 确实进入参考分支，强度生效 |
| 反推单图 | 图 1 | 单图反推指令的输出 | 反推读取原图，实际输出进入生成分支 |
| 反推双图 | 图 1 + 图 2 | 双图反推指令的输出 | 反推仍只读图 1，指令按双图语义；图 2 参与生成 |

**已确认的标准：**

- 应用新任务遵循用户提供的“全开关（反推 + 单双图 + 手输）”标准流程，不能用其他 Krea2 编辑编码链替代。
- 标准模型组合为 Moody-Mix premium、FP8 文字理解、V3 转真人 LoRA + `k2_nice_body`；人物 LoRA 可另加。
- 保留 8 步、CFG 1、euler、beta57、Easy_QwenEdit2509 等标准接线与参数。生成图分别按标准降饱和、缩放；反推读取未处理原图。
- 反推种子独立于出图种子；反推与手输是互斥来源，不能把两段提示词混合后执行。
- 已含主触发词的完整手输提示词直接使用，不能重复追加触发词。
- 旧 `uncensored` 字段可兼容读取，但不再改变应用新转真人任务的标准模型组合。

**实现基线与限制：** 当前选择双图但没有不同的图 2 时，会回退为图 1 兼作图 2，并返回说明。图 2 的作用是外观参考；历史验证不证明精确复刻某个不同人物的五官。

**本次建议 D01：** 正式双图任务要求两张明确、不同的输入图，缺图时不提交双图任务；单图模式显式采用单图契约。这会改变上述回退行为，须在产品确认后单独实施和验证。本轮文档不改变运行逻辑。

历史手工无审查 JSON 是独立保留的 ComfyUI 变体，已另行验证四组合；它的模型不能写入应用标准转真人任务的默认需求。

## 8. 视频功能重新归类

### 8.1 视频创作与执行方式

| 编号 / 能力 | 输入与目标 | 核心规则 | 状态 |
| --- | --- | --- | --- |
| V01 视频提示词创作 | 创作要求、参考素材、4–60 秒时长与比例 | 长视频写分段提示词，前后段内容连续；多方向各是独立候选 | 已确认 |
| V02 两遍生成 | 提示词、参考或首帧、生成参数 | 一采 → 放大 → 二采；保留一采预览及可重拍存档 | 实现基线 |
| V03 SelfLift 接续 | 提示词、参考或首帧、上下文与采样参数 | 每片段低清采样 → 高分辨率采样；以前段尾部画面与声音接续，再拼整条 | 已确认 / 实现基线 |
| V04 重拍指定时间 | 已有两遍生成结果、时间范围、新种子，可改该范围的提示词 | 读取存档重画指定范围，生成新版本，原片保留 | 已确认 |
| V05 从第 N 段重出 | 已有 SelfLift 任务及保存的片段计划 | 保留此前片段，从指定片段重新接续并拼接，新结果保留源关系 | 已确认 |
| V06 从已有视频续写 | 生成结果、已导入视频或本机视频作为起点 | SelfLift 先探测并按需要规整起点，成片包含原起点 + 新生成内容 | 已确认 |

重拍时间范围与从某片段重出是不同功能：前者属于两遍生成的局部重拍；后者属于 SelfLift 的尾部接续重出。续写起点是前置成片素材，不是普通参考视频。

加速 / 完整模式采用对应主模型及采样步数组合，后续仍能覆盖当前支持的参数。两遍生成使用一采百万像素与放大倍率计算成片尺寸；SelfLift 的低清采样比例用于内部阶段，成片尺寸按其工作流契约计算。

### 8.2 SelfLift 时长与预览

以下为**已确认**的规则：

1. 总时长大于 15 秒时，前段尽量采样满 15 秒，最后一段补余量；上下文重复帧从接续段扣除。
2. “请求时长”“提示词段数”“实际采样片段数”“拼接后帧数”分别记录。上下文与帧数约束可能让实际片段多于提示词段数。
3. H3 以 24 fps、`17n+5` 合法采样帧数执行。验收按保存的帧计划判断，允许量化误差，不要求恰好 30.000 秒。
4. 新任务保存分段长度和提示词映射；重启恢复、同参数重出、从第 N 段重出沿用该计划。历史任务缺少新字段时沿用旧计划规则。
5. 低清采样结束即能取得低清预览，此时任务仍在运行，高分辨率结果尚未完成。低清预览与首个完整片段分别记录类型。
6. 续写时，所选时长指新增内容时长。生成计划补偿首个新片段要剪掉的上下文，不能将上下文算进新增内容。
7. 前段或续写起点不足所选上下文长度时，在提交相关采样前拒绝，并保留可处理的具体原因。

参考计划：22 帧上下文、不带续写起点时，20 秒为 `[362,141]`，成片 481 帧；30 秒为 `[362,362,56]`，成片 736 帧。其他上下文档位按自己的计划计算。

### 8.3 视频与音频参考

**已确认 / 实现基线：**

- 图片、视频、音频各自编号，图片最多 9 张，参考视频和参考音频各最多 3 段，总参考数量最多 12。
- 参考视频和参考音频每段 2–15 秒，各类总时长分别不超过 15 秒；视频中参与参考的声音计入音频限额。
- 视频可只用画面、画面与声音、只用声音；音频可作为声音参考或配音。纯参考音频不能独立构成参考输入。
- 配音最多一段，不按参考音频编号和限额计数；长视频按实际分段切配音。
- 参考素材截取起止时间与实际使用帧数记录一致；每段生成如何重复使用参考素材按当前流程说明。
- 写提示词的聊天模型接收素材用途说明及视频截帧；不能据此声称它完整看过视频或听过音频。
- 参考模式、首帧模式、纯文字模式分别遵循素材契约；首尾帧与尾帧生成暂未接入。

## 9. 任务状态、结果与恢复

### 9.1 统一的业务状态

| 状态 | 含义 | 应保留的信息 |
| --- | --- | --- |
| 排队 | 已建立任务，等待执行资源 | 请求时间、资源等待原因；有实际队列信息时记录排位 |
| 运行 | 正在编码、采样、放大、接续、拼接或存文件 | 当前阶段、进度与耗时；视频另记录片段进度 |
| 完成 | 当前任务预期结果已生成并保存到本地 | 实际文件、尺寸 / 帧数、耗时和执行参数 |
| 失败 | 当前任务无法继续达到预期结果 | 原始错误及所属阶段、已有中间结果、后续可重试条件 |
| 停止 | 用户终止执行 | 停止时刻及已留下的结果；部分结果另行标记 |

**实现基线：** 图片组内每张都有状态；视频任务有整条状态。两遍生成被停止后可能保留低清部分结果，必须结合 `partial` 判断，不能仅凭有视频文件就认作完整成片。

**本次建议：** 统一业务解释和必要记录要素，继续沿用现有图像 / 视频存储与执行器。预览可用、部分结果、文件已清理均是结果属性，不新增一套相互冲突的任务状态。

### 9.2 一致性与异常

- 完成状态以服务端保存的任务及真实执行结果为准；迟到的进度事件不能让已完成任务重新变成运行。
- 断线或服务重启后，先查已保存的执行标识、ComfyUI history / queue 与已有片段，恢复对应任务；不要重复提交正在执行或已经成功的任务。
- ComfyUI history 成功后还要完成输出获取与本地保存，才满足应用完整结果的验收。
- 同参数重出保存来源关系；只换种子的重出另记录新种子。相同参数不等于对模型输出作绝对逐像素保证。
- 预览 / 部分结果可以早于完整成片；它们不能覆盖原素材、原完整结果或冒充后续片段已完成。
- 模型文件、节点、参考素材或重拍存档缺失时，记录确切缺项；不悄悄替换工作流来制造成功。
- 资源不足、余额不足、认证错误、实例失效、服务未启动、执行错误分别记录；缺货不算功能验证通过。

### 9.3 数据安全与资源管理

- 删除节点 / 画布需保持项目索引与文件一致；中途文件移动失败则恢复，删除进行中阻止同范围启动新任务。
- 删除用户资产库目录引用不删除原文件；生成结果、源素材和远程存档的删除范围分别确定。
- 模型配置及项目数据可在工作文件夹共用；密钥保留在本机配置，不进入共享项目或文档。
- 生图与视频分别绑定 ComfyUI / AutoDL 目标，生图和视频不能配置为同一个 AutoDL 实例。
- 生图保留局域网与 AutoDL 两种目标，视频沿用当前 AutoDL 目标；实例存在不等于服务、节点和模型可用。
- 模型上传、链接下载、管理自有模型与 LoRA 保留；公共模型库文件沿用只读规则。
- 实例空闲关机沿用既有设置，程序任务运行和模型传输期间不认作空闲；处理资源时保留他人的任务。
