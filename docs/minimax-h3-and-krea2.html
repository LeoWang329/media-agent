5 份子报告 Krea2：13B 单流 MMDiT H3：33B 视频+音频 本次未跑生成 · 未重启实例

先纠正一个前提：这两个不是同一类东西，不存在「选哪个当底模」。

MiniMax-H3 是视频 + 音频模型（768p / 24fps / 4–15 秒）；Krea2 是静态图像模型。把 HF 官方组织页 20 个仓库全枚举一遍， MiniMax 没有任何 text-to-image / image-to-image 的开源底模，Hailuo 系列也没开源权重。

→ 出真人照片继续用 Krea2；把真人照片变成视频才用 H3。真实关系是串联，不是二选一。

02 — 身份

两个模型到底是什么

MiniMax-H3

33B 全模态视频模型

MiniMax（稀宇科技）2026-08-03 开源。33B dense 单流 Transformer，输出 768p 视频 + 32kHz 立体声音频，4–15 秒 / 24fps。 任务分 fl2va（首尾帧）/ ref2va（参考图视频音频）/ hybrid（混血）/ t2va（纯文本）。

  • 文本编码器 = Qwen3-VL-32B（显存大头）
  • 三个 VAE：video / audio（audio 必须 fp32）/ music
  • ComfyUI 原生支持（0.30.0+，基础流程不需要第三方节点包）
  • 许可：MiniMax H3 Community License，排除欧盟 / 英国 / 韩国 / 美国（中国大陆可用）
Krea2（K2）

约 13B 自研单流 MMDiT

Krea AI 自研，2026-05-16 闭源线上版上线、2026-06-23 开放权重。ComfyUI 源码自述 "Krea 2 (K2) — single-stream MMDiT"。

  • 文本条件 = Qwen3-VL-4B 的 12 层 hidden states（内部 txtfusion），conditioning 模板与 Qwen-Image 相同（源码注释原文）
  • VAE 与 Qwen-Image 共用（qwen_image_vae.safetensors）→ 画质天花板同源
  • shift = 1.15 已写进 class Krea2，工作流里不要再加 ModelSampling 节点
  • 许可：Krea 2 Community License（不是 Apache / MIT）；与 flux1_krea_dev 没有血缘

为什么要知道这个：社区共识是「编辑用 Qwen-Image-Edit，生成用 Krea2，视频用 H3」。 Krea2 没有原生编辑管线——换背景 / 换材质会把主体「重新诠释」一遍；而你编辑档走 Qwen-Image-Edit 2509 / Ostris 这条路是对的，别试图用 Krea2 替代。

结论 1

ref2v 上 PDD 明显更好

同一份第三方实测（1344×768 / 124 帧 / 同 seed）：PDD 8 步的细节锐度比 lightx2v 8 步高 42%（7.986 vs 5.630）， 而 lightx2v 8 步相对 20 步成片档是过平滑的（−22%）。但 i2v 上两者只差 1.5%——不能跨能力外推。

结论 2

shift 按作者的推荐值配对

544p 系 turbo 推荐 12 / 3，768p 系 turbo 推荐 6 / 3。 但这不是「错一个数字就崩」的硬约束 —— 见 09 补充里的更正。

结论 3

两个「不能叠」

蒸馏 LoRA 之间不能叠加；也不要叠 step-caching（blockcache / EasyCache）。角色 / 风格 LoRA 可以正常叠。

一条必须知道的限制

ComfyUI 里的 H3 没有真正的 video-to-video。三个 H3 节点都从空 latent 开始，参考图 / 关键帧 / guide 是 conditioning——每一步被重新注入，但从不被去噪，也没有 denoise < 1 的路径。

→ 参考视频里没有任何一帧会保留到输出里。你拿到的是一个全新生成、近似跟随参考运动与节奏的视频。「拿一段源视频换角色」在本地 ComfyUI 做不到。

采样参数：你有 4 处可以立刻改

改动 1 · 步数

10 步 → 8 步

官方 turbo 蒸馏点就是 8 步；A2R LoRA 官方 card 也写 8 步 / CFG 1 / 2048。多出的 2 步买到的是「更细的纹理」而不是「更对的构图」， 收益低于把时间拿去换 seed。

改动 2 · 底模

fp8_scaled → int8_convrot

见上表。零成本，加载器与结构都不变。

改动 3 · CFG / 负面词

CFG 必须 = 1，负面提示词删掉

turbo 是 RL 无 CFG 训练 + guidance 蒸馏出来的，CFG 一开就过饱和发灰；CFG=1 时负面提示词被忽略，写了白写。 scheduler 建议 simple 做基线（beta 当风格旋钮）。

改动 4 · 编辑档底模

JAV 片感 → RAW 棚拍

你现在编辑档用 moodyAmateurMixKrea2_3JAVStyle（官方定位「日式素人 JAV 片感、略糊、生活化」）； 想要更锐的写实，换 _4RawStudioShot（RAW 棚拍、真实皮肤纹理）或 Moody-Krea-Mix-v2G。

turbo 不是「低质快版」

官方 README 原文

"The Raw model is an undistilled checkpoint without any step / cfg guidance distillation and posttraining… In short, TRAIN on Raw and RUN on Turbo."

→ RAW 连 PO / RL 都没做，换来的是多样性、可塑性、可训练性；turbo 走完整管线（PO → RL → TDM 蒸馏），换来的是审美完成度 + 速度 + 2K。

05 — NSFW 支持度

两边都是同一个格局：官方有对齐、本地有绕过、社区成规模

差别在形态和约束，不在「谁更开放」。下面按三层拆：底模能力 / 文本编码器 / 生态。点标签切换。

MiniMax-H3
  • 许可 AUP 20 条里没有一条明确禁色情（无 pornography / sexual 字样）。最接近的是第 5 条「禁止绕过官方安全护栏」和第 15 条宽泛道德兜底。官方 license 原文

两个完全独立的用法

用法 ① 锐化 LoRA
loras/minimax/minimax_h3_lms_v1.0_r64.safetensors · 1.24 GB

挂在 LoraLoaderModelOnly，权重 0.2–1.0。同分辨率把 H3 偏软的输出「回锐」，不增加像素。 必须同时挂 MiniMaxH3AddGuide（frame_idx = 0），否则不工作。

用法 ② 潜空间放大器
latent_upscale_models/h3_upscaler_lms_v0.1_fp32.safetensors · 1.38 GB

当 SelfLiftH3Sampler 的 upscaler_model（第 9 个控件），rho=0 外部提升器模式： 前段低分辨率采样 → 学习式 latent 提升 → 高分辨率收尾。

放大器那两个文件名是同一份文件：实机 h3_upscaler_lms_v0.1_fp32 与 h3_upscaler_sharpness_2000steps_v0.1_fp32 是同一个 AutoDL blob（md5 都是 ac7519f3…，都是 1,381,153,616 字节）——作者把旧名重命名成了新名，本地缓存留了两个名字。

它不是 LoRA，是从 LBH-123-AI/Minimax_h3_latent_Upscaler 初始化、再用和 LMS LoRA 相同的 sharpness 数据集微调 2000 步得到的。官方推荐 fp16 版，你机器上装的是 fp32 训练存档（换 fp16 省显存，画质无影响）。

_r64 和 _r64_r2 是不是同一份权重？

是。逐张量比对（516 / 516）显示差异只有 1–2 个 fp16 ULP（最大 2⁻¹²，全局相对差 5.1e-4，余弦 ≥ 0.9999998）。 决定性证据：_r2 的元数据 sshs_model_hash 仍然等于 r64 的数据段哈希，同时多出 hash_modifier_nonce / hash_modifier_time 两个字段 → 二次保存 + 有意的哈希改写，不是第二次训练。选哪个都行，建议以和官方同名的 _r64 为基准。

LMS 与「转真人」的关系

LMS 不改身份、不改风格，只改锐度。它对这个场景的价值在后期：真人化角色最怕的不是糊，而是「塑料感 / 涂抹感」， 而 LMS 的定位正是「把清晰、照片级的细节加回偏 soft 或过度平滑的输出」。两条硬限制：一致性靠图像阶段和参考图，不靠 LMS； LMS 训练在 ref2va + guide latent 上，混用原生参考图是作者标注的「实验性，可能不会更好」。
