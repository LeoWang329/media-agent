# P23 Krea2 指令编辑报告

「放一张图进去，指定改哪儿，但不用涂抹」的前一半：**放一张图 + 写一句话，模型自己找地方改**。规则在 `docs/dev-plan.md` 5.34，怎么定下来的见 `docs/plan-image-edit.md`。

## 做了什么

「Krea2 出图设置」的「起图」那一排从两个按钮变成三个：**文生图 / 四视图 / 编辑**。编辑档放参考图 + 在框里写一句话就出图，不用掩码。

- **怎么画的**：照生图实例上的 `T07-Krea2图像编辑krea2edit版单图双图`：`UNETLoader(krea2_turbo_int8_convrot)` → `LoraLoaderModelOnly(krea2/krea2_identity_edit_v1_1)` → `Krea2EditModelPatch`（`source_latent` 接参考图缩放后的 `VAEEncode`）→ `KSampler(latent_image = EmptySD3LatentImage, denoise 1, 8 步, cfg 1, euler/simple)` → `VAEDecode` → `PreviewImage`。正面词是框里那句话，负面词同一个节点、空 prompt。
  这不是 img2img：`denoise 1` + 空潜变量，是「把参考图当参考、从空白重画一张」，改哪儿由正面词决定，所以不用掩码。
- **和四视图共用一条路**：`kreaGraph` 里 `withRef = mode !== 'text'`。差三处：LoRA 换成身份编辑那个、指令用框里的话（不追加 `FOUR_VIEW_INSTRUCTION`）、参考图按**出图尺寸**缩放（四视图仍固定 1024×1024）。
- **默认值照 T07**：官方 Turbo 底模、`qwen3vl_4b_uncensored_int8_convrot` 文字理解、`qwen_image_vae`、身份编辑 LoRA @1、8 步、CFG 1、euler/simple、1024×1024、`ref_boost` 1。
- **拦住的情况**：没选参考图时说「编辑还没选参考图」，一张都不发；参考图后来删了、临时文件清了又没下载过，这组算失败，说「编辑的参考图找不到了」。
- **尺寸**：和四视图一样要 16 的倍数（`EmptySD3LatentImage` 的要求），面板的尺寸下拉和「自己填」也按 16 收，自己填的取最近的 16 的倍数。
- **一组的 kind 是 `edit`**：框下面那组标「编辑」，大图参数里「起图」写「编辑 · 相似度 N」。
- **界面上写清局限**：没提到的部分不保证像素不动（背景、姿态、构图可能跟着变一点），人物长相靠身份编辑 LoRA 保住；要「只改一块、别处一个像素不动」用局部重绘。这句话就在「编辑」档的说明里。
- **假的 ComfyUI**：`krea2/krea2_identity_edit_v1_1.safetensors` 加进 LoRA 列表（原来没有这个文件，测试里发出去会被判「值不在列表里」）。

## 编辑方案（补做的一小步）

用户看过之后问「每个下拉项有个预设的参数和 lora 是吗」，于是「编辑」档下面加了一个 **编辑方案** 下拉（`KREA2_EDIT_PRESETS`）：

| 方案 | LoRA | 触发词 | 参数 |
| --- | --- | --- | --- |
| 身份编辑 v1.1（默认，照 T07） | `krea2_identity_edit_v1_1` @1 | — | 8 步 / CFG 1 / 1024×1024 |
| 身份编辑 v1.2 | `krea2_identity_edit_v1_2` @1 | — | 同上 |
| 换装 | `krea_outfittransfer` @1 | — | 同上 |
| 动漫转真人 V1 | `Krea2_Anything2RealCharacters-V1` @1 | `transform the image to realistic photograph` | 10 步 / CFG 1 |
| 动漫转真人 V3 | `Krea2_Anything2RealCharacters-V3` @1 | 同上 | 8 步 / CFG 1 / 2048×2048 |

- 触发词和推荐参数照作者在模型页上写的（Civitai 2808492 的 V1 与 V3 说明）；换装和身份编辑不吃触发词，它们吃自然语言指令。
- 选一个方案＝把这套 LoRA 和参数填进节点，之后照样能手改；**手动改过 LoRA 就显示「自己选的 LoRA」**。
- 服务端**不另存「选了哪个方案」**：照这一组的 LoRA 名字反认（`editPresetOf`），认出来且带触发词就把触发词放在框里那句话前面（`触发词\n\n你写的话`）。手写 LoRA 名字也吃得到，改强度不影响认。
- 一个边界：LoRA 列表里挂两个名字不同的 LoRA 就不算任何方案。要加新方案就往 `KREA2_EDIT_PRESETS` 里加一条，界面和服务端都跟着走。

**这一步没在真机上验**（要再开那台）；「动漫转真人 V3」的参数是照作者写的填的，出来好不好看要跑了才知道。

## 和计划不一样的地方

- **文字理解模型**：计划 2.2 写的 `qwen3vl_4b_uncensored_int8_convrot`，就是 T07 用的那个，照做了。
- **参考图缩放**：计划说先照四视图用 `keep_proportion: 'resize'`，实机对比 `resize` 和 `pad` 之后再定。这一步先按 `resize`。
- **`InpaintCropImproved` 的必填项数**：计划里写 24，实际是 **25**（接进来的 `image` 加 24 个参数），`docs/plan-image-edit.md` 和 5.35 都改过来了。

## 双图（用户后加的要求：「你要支持两张图」）

T07 全名 `T07-Krea2图像编辑krea2edit版单图双图`，本来就支持一张和两张。节点注解把顺序写死了：**场景在前、主体在后**。

| | 图 1（`reference`） | 图 2（`referenceB`，可不选） |
| --- | --- | --- |
| 角色 | 场景：构图、背景、姿势 | 主体：人物长相 / 身份 |
| 相似度 | `refBoostA`（新增，默认 1）→ `ref_boost_a` | `refBoost`（现有那个）→ `ref_boost` |

- 接线：图 2 多一路 `LoadImage → ImageResizeKJv2 → VAEEncode`，接 `source_latent_b` / `source_image_b`，两个 `Krea2EditGroundedEncode` 的 `image_b` 也给它。
- **没选图 2 时接线和单图一模一样**（`_b` 一个都不接），这条是单测里拿整张图的 `toEqual` 卡住的。
- 界面：编辑档两个选择器（「图 1 · 场景」`aria-label` 还是「参考图」，老用例不受影响；「图 2 · 人物」是「第二张参考图」），**选了图 2 才出「图 1（场景）相似度」那一行**；大图参数双图写「编辑（双图）· 场景 1.5 / 人物 2」。
- 服务端：两张都上传（顺序场景在前），第二张找不到时报「编辑的第二张参考图（人物）找不到了」。
- 预设不存参考图，两张都不存；`referenceB` / `refBoostA` 在类型里是**可选**的，老节点读出来当「没选 / 1」。

测试（这一步加的 4 条）：`packages/shared/test/imageJob.test.ts` 里 `kreaGraph 的双图` 三条（单图整张 `toEqual`、双图三处 `_b` + 两个相似度 + 两张各走一次 VAEEncode、四视图不受影响）、`packages/server/test/krea2.test.ts` 一条（两张都传、顺序和内容对得上）、`tests/e2e/18-krea2.spec.ts` 一条（两个选择器、第二个相似度选完图 2 才出现、mock 收到两个 `LoadImage` 和两处 `image_b`、两张上传、大图参数写着双图）。

**真机没验成**：第一次是连续 7 次「当前算力规格暂无库存」开不上；后来开上了，把 T07 读了（见上一节，抓到一个 `grounding_px` 的差异并改掉），但真跑的时候那台的 GPU 崩了（连单图基线都 `CUDA error`），实例随后自己 `shutdown`。双图的三层测试全绿，线级也确认发对了（`referenceB` 记着、`_b` 那一路接上、两张都上传）。脚本备好：`outputs/real/boot-retry.mjs`、`outputs/real/fetch-t07.mjs`、`outputs/real/verify-edit.mjs`。

## T07 读下来了（四个问题的答案）

那台后来开上了一次，用 `outputs/real/fetch-t07.mjs` 把 `T-图像-Krea/T07-Krea2图像编辑krea2edit版单图双图.json` 读下来存到 `outputs/real/T07.json`。**T07 存的就是单图**：`source_latent_b`、`image_b` 全是空的（双图那半边得自己接），所以双图按节点注解做是对的。

| 项 | T07 的真值 | 我们 |
| --- | --- | --- |
| LoRA | `krea2/krea2_identity_edit_v1_1.safetensors` @1 | ✅ 一样 |
| 底模 / CLIP / VAE | `krea2_turbo_int8_convrot` / `qwen3vl_4b_uncensored_int8_convrot`(type=krea2) / `qwen_image_vae` | ✅ 一样 |

## 真机验证：线级对了，卡坏了

开上实例之后按三条跑（`outputs/real/verify-edit.mjs`）：① 单图基线 ② 双图 ③ 转真人。

- **线级全对**：三条都真的发到了那台 ComfyUI 上。双图那条 `params.krea.reference` = 站台、`referenceB` = 动漫女孩；转真人那条 `kind=edit`、LoRA = `Krea2_Anything2RealCharacters-V3`、**发出去的正面词第一行就是 `transform the image to realistic photograph`**（触发词自动加上了）。
- **执行全崩**，但**不是我们这条流程的事**：连最简单的「单图基线」（就是今天早些时候跑通过的那条）也报 `出图出错（Krea2EditGroundedEncode）：CUDA error: an illegal memory access was encountered`，随后 ComfyUI 整个起不来（`/system_stats` 一直回 AutoDL 的 404 页），再过一会儿实例自己变成 `shutdown`。**是那台的 GPU 挂了**，前一次还是 `unspecified launch failure`。
- 想过重启换卡（`outputs/real/powercycle.mjs`）：关掉再开，ComfyUI 6 分钟没起来，最后实例又回到 `shutdown`。就没再耗。

所以真机这一步**没验成**，卡在机器上，不是代码上。下次那台能用时跑一遍 `outputs/real/verify-edit.mjs` 就行（三条会各自兜错，哪条挂了不影响后面）。三条出图要看的：单图 = 大衣变红皮衣；双图 = 图 2 的女孩放进图 1 的站台；转真人 = 动漫女孩变成真人照片。

## 后面改了：编辑档从那台 ComfyUI 的 Krea2Edit 换成作者那套 Ostris

上面那套（`Krea2EditModelPatch` + `Krea2EditGroundedEncode`）后来**在真机上被证明配写实/转真人 LoRA 是坏的**，所以编辑档整条换掉了。四视图没这个问题，继续用 Krea2Edit。

### 怎么发现的

用户拿 T07 那套跑「动漫转真人」，出来的图洗白、发粉、还是动漫。在真机上做了 8 组对照：

| 跑法 | 结果 |
| --- | --- |
| 他那条（补上 `vae` / `source_image` / `target_latent` 三个口） | 洗白发粉（补口只是消掉了条纹） |
| 同上，**摘掉 LoRA** | 一样坏 |
| 同上，换 fp8 底模 | 一样坏 |
| 同上，换中性提示词 | 一样坏 |
| **四视图那条路** + `krea2_4panel` | ✅ 完美角色设定图 |
| 四视图那条路 + 真人化 LoRA | ❌ 边缘露原图、中间花掉 |
| **纯文生图** + 真人化 LoRA + 触发词 | ✅ 写实得很干净 |

也就是说：`Krea2EditModelPatch` 只吃 edit 系的 LoRA（`krea2_4panel` 这种），换成真人化 LoRA 就崩；同一个 LoRA 在**文生图**里完全正常。**不是底模、不是编码器、不是提示词、不是参数。**

### 换成什么

作者（`Krea2_Anything2RealCharacters` 那个）自己给的节点包：[ostris/ComfyUI-Krea2-Ostris-Edit](https://github.com/ostris/ComfyUI-Krea2-Ostris-Edit) v1.0.1，两个节点 `TextEncodeKrea2OstrisEdit` + `Krea2OstrisEditModelPatch`，**给用 ai-toolkit 训的 edit LoRA 用**——真人化 V3 正好是这类。README 里写的接线就是我们实现的那条。

顺手把作者示例里的 `FluxKontextImageScale` 换掉了：它把图锁在 ~1MP（880×1184），而 V3 是 2K 训的，**出来明显发糊**。换成 `LayerUtility: ImageScaleByAspectRatio V2`（长边 2048、`round_to_multiple 16`），出图尺寸跟着缩放后的参考图走。
