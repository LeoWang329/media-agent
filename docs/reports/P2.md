### 服务端

- 资产库接口按第 7 节做了：导入、移除、列出导入的文件夹，弹窗选文件夹，子文件夹树，列文件夹里的图，搜索，缩略图。`/assets/reveal`（在资源管理器里显示）属于 P3 的上传清单，没做。
- 列文件夹：只列 jpg、jpeg、png、webp，heic、heif、gif 也列出来但标不支持；按文件名排序。打开文件夹时超过 5 秒没扫过才重新扫，「刷新」强制重扫。搜索按文件名、不区分大小写、子串匹配，搜全部导入的文件夹，最多 200 条；搜索用的文件清单同样超过 5 秒才重扫。读不了的子文件夹跳过。
- 缩略图：长边 256，JPEG 质量 80，存在本机配置目录的 `thumbs/`，文件名是 sha1(路径 + 修改时间 + 大小)。槽位、卡片、消息里的小图也走这个缓存。
- 放进槽位（`POST /api/canvases/:id/images`）：按 5.6 算 sha256，同一画布里有同样内容的图就复用；否则复制进 `images/<sha256>.<ext>`，太大缩到长边 5760、太小放大到短边 256，处理后仍超过 30 MB 转 JPEG 从质量 90 往下降；再生成发给模型的 `<sha256>.llm.jpg`；写 `images.json`。画布详情接口里带上了 `images`，前端用它显示文件名和「尺寸不符」。
- 发送：拿当前路径最后一条消息的快照和节点现在的槽位、时长、比例比，按 5.4 的五种情况算出说明和要带的图，存进 user 消息；发给模型时每张图前面一行 `<Picture N>`，图用 `.llm.jpg` 转成 data URL。找不到图的记录时，这条回复按失败显示原因。
- 接口参数里的文件路径（导入的图、列文件夹、子文件夹树、缩略图）必须在导入的资产文件夹或工作文件夹里，否则返回 403。
- 本机 `config.json` 的读改写排队，改工作文件夹和导入资产库文件夹同时发生也不会互相覆盖。

### 前端

- 左栏资产库：搜索框（停手 300 毫秒再搜）、「导入文件夹」（弹系统窗口；返回 501 或弹窗出错时显示路径输入框）、文件夹树（根文件夹右键「移除（不动文件）」）、网格上方显示当前文件夹名或「搜索结果 N 个」和「刷新」、图片网格（缩略图加文件名，不支持的格式灰显「不支持」）。单击选中，Ctrl 加选，Shift 连选，双击放进下一个空槽位，拖动时带上选中的全部图。
- 对话面板输入框上方：一行 9 个槽位，填了的显示缩略图和编号，悬停出现删除；超出 H3 尺寸的图标红「尺寸不符」；从资产库拖进来放图，也能从 Windows 文件夹直接拖进来，拖到已有图的槽位上替换它，槽位之间拖动调顺序；第一个空格子里有个淡灰的「+」，标着下一张图落在哪；点一下槽位弹出选图窗口（标题写「放进 N 号」或「替换 N 号」），单击一张就放进这一格。右边是时长（4 到 15 秒）和比例下拉。放图时显示「正在放入 N 张图…」。
- 用户消息：气泡上方一行灰字是程序加的说明，下方是这条消息实际发出的图，带编号。
- 节点卡片：标题下面一行 9 格小图，空位是虚线框。
- 切换消息版本时，槽位、时长、比例换成新路径最后一条消息当时的；有还没发出的改动时先弹确认。
- 设置页最下面加了「资产库文件夹」列表，每行有「移除」。

「点一下槽位，再从资产库里选图」是访谈记录第 8 条写了、计划 5.1 漏了的操作，报完 P2 后你说要做，已经加上，计划 5.1 也补了这句。

这一步后来又改了两回：第一版只让有图的槽位点得中，你试的时候一张图都还没放，点的都是空格子，什么都没发生；改成空槽位也点得中之后，没放图时点哪个格子选中的都是 1 号，看上去像坏的。现在改成点槽位直接弹选图窗口：

- 窗口标题写清楚图会落在哪一格（「放进 5 号」或「替换 1 号」），槽位区里那一格同时高亮；点空格子时弹的是第一个空位，因为槽位中间不留空。
- 窗口里就是左栏那套资产库（搜索、导入文件夹、文件夹树、图片网格），完全同一个组件，只是单击一张图就直接放进去并关窗；按 Ctrl 或 Shift 多选不关窗，下面出现「放入选中的 N 张」，一次填好几格。Esc、点空白处、「关闭」都能关。
- 既然有了选图窗口，就把原来的「选中槽位→双击左栏的图」去掉了（`pickedSlot` 从 store 里删了），两套做同一件事没必要。左栏双击还是放进下一个空位。

端到端测试里相应改了一步：点 1 号槽位弹窗「替换 1 号」、单击一张换掉；点第 9 个空格子弹窗「放进 5 号」、Ctrl 选两张一次放进 5、6 号。

### 从 Windows 文件夹直接拖图进槽位

你试的时候根本没导入过文件夹，直接从资源管理器拖图才是你想要的用法，这一条原计划没有，补上了，计划 5.1、5.6 和接口表也补了。

- 新接口 `POST /canvases/:id/images/upload?name=&nodeId=`，请求体就是图片内容（`application/octet-stream`，最大 64 MB）。存进画布文件夹、按 H3 要求处理、生成小图、按 sha256 去重，都和从资产库放图走同一套代码。
- 浏览器只给得出文件名和内容，给不出本机路径，所以这种图的 `originalPath` 存空字符串（P3 的上传清单本来就指向画布里处理过的那份，不受影响；「在资源管理器中显示原图」对这种图做不了）。
- 只按扩展名收 jpg、jpeg、png、webp，其余的忽略；一张能收的都没有时提示「只支持 jpg、jpeg、png、webp 格式的图片」。支持的扩展名这下只写在 shared 里一份，前后端共用。
- 拖了但没对准槽位区时，浏览器默认会把图片当新页面打开、把画布顶掉，所以在 App 里挡了一下：拖错地方就什么都不发生。
- 没验证的：真的从资源管理器拖。测试里是在浏览器里现造两个 File、按拖放的样子放到槽位上，走的是同一条代码路径。

### 计划没写死、我定下的几件事

- 多张图拖到已有图的槽位上：第一张替换这一格，其余接在后面的空位。槽位不够时放得下几张放几张，提示多出几张没放进去。
- 槽位之间拖动是「挪过去」不是「互换」：把 4 号拖到 1 号，原来的 1 到 3 号往后挪一位。
- 什么算「换图」：长度不变，换进来的都是之前槽位里没有的图，才只发换掉的那几张；换进来的是原来别的位置上的图，按「调了顺序」处理，全部重新编号重发。
- 全部图都删掉时，说明照 5.4 原文会写「以下是当前全部 0 张参考图」。
- 发给模型的小图在放进槽位时生成，长边用这个节点当时选的模型配置；之后改发图长边或换模型配置，已经放进去的图不重新生成。小图不放大，800×600 的图发出去还是 800×600。
- 缩放后按原格式保存，JPEG、WebP 质量 90，PNG 无损；转 JPEG 时透明的地方补白底。手机照片的旋转标记先转正再算宽高。
- GIF 也列出来灰显「不支持」：计划第 2 节写了 GIF 不支持，6.3 只提了 heic、heif。
- 文件名里的数字按大小排，`img2` 排在 `img10` 前面。
- 图片网格一直用虚拟滚动（计划写超过 200 张才用），图少时看起来没区别，只留一套代码。
- 还没选中节点就双击资产库里的图，画布顶上提示「先在画布上点一个节点，再往槽位里放图」。
- 端到端测试里弹不出系统选文件夹窗口，测试把这个接口改成返回 501，走路径输入框导入。
- P1 的服务端测试原来用假的槽位 id，现在发消息要读真图，改成先生成真图放进去；第一条消息现在带「本次没有参考图…」的说明，那条断言跟着改了。

## 怎么试

1. `npm run dev`，打开 http://localhost:5173 ，设置好工作文件夹和 mock 模型配置（同 P1）。
2. 进一个画布，左栏点「导入文件夹」，选一个放着图片的文件夹。想用测试图的话，先跑一次 `npm run test:e2e`，它会生成 `tests/fixtures/images/`。
3. 点中一个节点，双击三张图：槽位显示 1、2、3，卡片上出现小图。发「写一个」：回复里「收到 3 张图：<Picture 1>、<Picture 2>、<Picture 3>」，你那条消息上方有「参考图共 3 张…」。
4. 再拖一张图到 2 号槽位上，发「改一下」：「收到 1 张图：<Picture 2>」，说明里有「换成了」。
5. 鼠标移到 1 号槽位点「×」，发「再改」：「收到 2 张图」，说明里有「重新编号」。
6. 时长改成 12，发一句：说明「视频时长改为 12 秒」，「收到 0 张图」。
7. 不导入文件夹也能用：直接从 Windows 文件夹里选几张图拖到槽位区，按你选的顺序填进空位；拖到某一格上就替换那一格。
8. 点任意一个槽位会弹选图窗口，标题写着图会放到哪一格；窗口里单击一张就放进去，Ctrl 多选后点下面的按钮一次放几张。
9. 也可以试：槽位之间拖动、Ctrl 多选几张一起拖进来、搜索框搜文件名、放一张 6000 像素的大图后到工作文件夹 `canvases/<画布 id>/images/` 里看副本尺寸。

这样试会写你本机真实的配置 `%APPDATA%\media-agent\`（导入的文件夹和缩略图缓存）和工作文件夹。我验证时没写过，本机配置目录现在还不存在。
