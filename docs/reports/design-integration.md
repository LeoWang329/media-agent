# 设计原型对接报告

对接方案在 `docs/design-integration-plan.md`，原型在 `web/prototype/`。所有改动在 `ui-prototype` 分支上，还没提交。

## 做了什么

设计师的原型整套接进了系统：首次设置、首页、画布工作台、对话面板、资产库、上传清单、拼图、系统提示词原文、设置页。

- **样式原样用**：`packages/client/src/design/` 里的 `app.css`、`canvas.css` 和原型文件逐字节一样；`home.css`、`settings.css`、`setup.css` 是原型三个页面里内嵌的样式，内容一样，只是缩进不同。搬进 React 和 Tiptap 后要补的几条单独放在 `glue.css`，不改原型的样子。
- **结构一比一搬**：页面层级、类名、文案照原型的 HTML 写成 React 组件，图标用原型那套。旧的界面组件和 `styles.css` 删掉了。
- **节点图自己画**：不再用 React Flow，照原型的写法做平移、缩放、拖动、连线、折叠、自动排整齐。React Flow 和 dagre 两个依赖删掉了。
- **逻辑沿用已经测过的**：接口、消息版本树、流式回复、撤销栈、@ 引用编辑器（外观换成原型的小标签）、图片处理。
- **服务端补的**：画布列表带封面图和正在生成的节点数；删画布后能从回收站恢复；叫停的回复上记标记；节点摘要带时长、比例、是否失败、是否在生成；槽位里原文件不在的图标出来；上传清单带文件大小；拼图接受文件名、能直接放进画布、能记住上次存到的库外文件夹；资产库文件夹带张数、能列出子文件夹里的全部图、读不了时说原因；检查文件夹能不能写入；在资源管理器里打开文件夹。
- **原型里没画、原来就有的，都留着**：从资源管理器直接把图拖进槽位（拖到有图的格子上是替换那一格）、节点卡片右键菜单、资产库多级子文件夹、手动重新扫描（在资产库文件夹的「…」菜单里）。
- **端到端用例**：原来 20 条全部改成新界面的点法，另加设置页自动保存、改名、首页、失败后接着聊再重试四条，现在 24 条。审查后补的其他检查加在已有用例里。

## 和方案不一样的地方

1. **没有每步停下来**。方案写的是每一步做完给你看；你说直接做完，所以第 2 到第 6 步连着做完了。
2. **原型的演示行为和需求文档写明的冲突时，按需求**：
   - 费用不到 1 块显示四位小数。原型是三位，几厘钱会显示成 0。
   - 拼图打开时编号默认不开、每格边长默认 1024（需求第 24 条）。原型是开着、1536。
   - 切换版本按开发方案 5.1：切到的那一版发出时的槽位、时长、比例和现在不一样，就换回那一版的；有没发出的改动先弹确认；换掉的槽位能 Ctrl+Z 撤回。原型只有「最后一条需求」换版本时才动槽位。
   - 回复里提示词框外面的文字按 Markdown 显示（开发方案要求）。原型是纯文字。
   - 「沿第 N 个方向往下改」照需求原文写。
3. **原型没画、按开发方案补的**：槽位里尺寸不符合 H3 要求（每边 256 到 5760 像素）的图，角上标「尺寸不符」，悬停写现在是多大（开发方案 5.6）。
4. **原型算错的一处，照原意改了**：打开面板时停在最后一条回复的开头。原型算位置时多算了面板顶部那一截的高度，会往下多滚一段，看不到「回复 · 时间 · 版本」那一行。
5. **需求没说、按原型做的，和以前的行为不一样**：
   - 首页新建画布后留在首页，新卡片闪一下、提示「建好了」，不再直接进画布。
   - 槽位里不放重复的图，再放同一张会提示「已经在槽位里了」。
   - 自动排整齐用原型的排法；岔出的新节点放在原节点右边 344 像素，有兄弟节点时放在最下面那个再往下 230 像素。
   - 岔出节点里复制来的消息收成一块，点开才显示；这些消息只能复制、看上传清单、看系统提示词、从这里岔出、沿方向继续，不能改这句、切版本、重答、打星、手动改。
   - 画面比例用原型的六个选项，末尾保留需求里的「自动」。

## 审查发现的问题和处理

做完后派了三个审查（还原得像不像、功能齐不齐、逻辑对不对），挑出来的问题整理成 29 条要修、5 条不修。修完又派了两个审查复查修改本身。

### 会丢数据或指错图的，都修了

- **设置页的模型配置**：改完切到别的分类再切回来，列表还是进设置页时的旧数据，再改一下会把刚建的配置和刚填的密钥删掉。改成列表放在页面这一层，切回来是最新的（`packages/client/src/pages/Settings.tsx`）。
- **生成中删画布**：回复还在往节点文件里写，写的时候会在原处重新建出画布文件夹，点「撤销」恢复时提示「这个画布已经在了」。改成先叫停这个画布上的生成、等回复存完再挪进回收站；改写已有节点文件时不再顺手建文件夹（`packages/server/src/llm/generation.ts`、`packages/server/src/routes/canvases.ts`、`packages/server/src/store/jsonFile.ts`）。
- **输入框草稿里的图片引用存的是编号**：存完草稿再挪槽位、删图，切回来或刷新后引用悄悄指到别的图。改成草稿里存图片 id（`packages/client/src/editor/document.ts`）。
- **手动改老回复的提示词**：小标签和存下来的 `<Picture N>` 按现在的槽位编号，这条回复带的却是当时那套图，上传清单和从它岔出的节点都对不上。改成按这条回复发出时带的图编号，@ 小窗也只列这条回复带的图（`packages/client/src/editor/PictureRef.tsx`、`packages/client/src/canvas/PromptBox.tsx`、`packages/client/src/canvas/RefPicker.tsx`）。

### 点不了、看不到的，都修了

- 弹窗里点出来的「…」菜单和提示条压在弹窗下面，点不了（资产库文件夹菜单里的重新扫描、从资产库移除因此用不了）。改成放进最上面那个弹窗里显示（`packages/client/src/ui/Dialog.tsx`、`menu.tsx`、`toast.tsx`）。
- 资产库图多时网格不自己滚、整个弹窗在滚，120 张以后的图加载不出来。补了三行样式（`glue.css`）。原型本来就有这个毛病。
- 确认框弹出后焦点在「取消」上，按回车是取消。改成落在确定按钮上。
- 打开节点多的画布会缩到 30% 以下，看不清。改成最小缩到 30%。
- 岔出、点提示条上的「去看看」后，新节点可能在视野外。改成挪进视野。
- 第一次点开某个节点时面板先空一下；收起面板的动画里输入框的图片标签变红；删掉被引用的图时两条提示条顺序反了。都修了。

### 和需求、原型对不上的，都修了

- 失败的回复点「重试」会多出一个版本并标「重答」。原型是原地替换，现在重试成功的不算新版本。
- 上传清单：一张图的副本文件不在，整张清单的路径都出不来，改成只影响那一行；标签按服务端返回的情况显示；拼图存到库外文件夹后「在资源管理器里显示」报 403，改成按图片 id 由服务端查路径。
- 拼图：存到资产库以外的文件夹时，提示条带「导入资产库」；槽位满了明说没放进去；导入的文件夹互相包含时下拉框里重复，去重了。
- 设置页：系统提示词删光后能新建空白的；换工作文件夹失败时一律给「去填写」；首次设置和设置页改浏览器标签页标题。
- 「正在写入工作文件夹…」只闪一下看不清，改成至少显示 0.65 秒；换页面清掉上一个页面的写入时间。

### 操作上的毛病，都修了

- 提示条上的「撤销」撤的是最近一步，不一定是它说的那一步。改成只撤它说的那步，之后又改了别的就不撤并说明。撤销失败不挪栈；删节点的撤销步骤在删除成功后马上记。
- 弹窗开着时按 Ctrl+Z 会撤销后面画布上的操作，改成不撤；焦点在下拉框里按 Ctrl+Z 也能撤销画布。
- 撤销让父节点重新折起来、选中的子节点藏起来了，面板还开着。改成收起面板。
- 连点时长加减，服务端先回来的结果会把后面还在排队的改动盖回去。改了。
- 界面先改、服务端写失败时，界面和服务端对不上。改成失败后重读节点。
- 刚拖完节点碰上一次刷新，节点跳回原位。改了。
- 从资产库多选放进槽位时，已经在槽位里的图也占名额，新图放不进去。改成先去掉重复的再算。
- 发送失败时输入框已经清空，草稿也被存成空。改成把内容放回输入框。
- 生成中点「改这句」「重答」「重试」没反应也不说。改成提示「正在生成，先叫停或等它写完」。
- 手动改提示词时用输入法打「@」，插图后「@」还留在文字里；从资产库挑图插进句子时光标丢了。都修了。
- 拖槽位、拖拼图格子到输入框上会插进一串字；从电脑里拖文件到有图的格子上没反应。都修了。
- 刷新过页面后某节点还在生成，切走再切回来对话停在半截。改成那边生成结束时重读所有看过的节点。

### 没修的

- 撤销删除、撤销展开后，恢复出来的节点有个淡入动画。只是观感。
- 拼图右栏的图不分批渲染。缩略图本来就是滚到才加载。
- 叫停时没写完的提示词框不给打星、手动改。没写完的框和解析出来的提示词对不上号，是有意的。
- 资产库图片的悬停提示没有宽高（扫描时不读尺寸）；往槽位放任何图都先盖一层「处理中」（本机快的话只是一闪）；原型地址栏 `#node=` 直接打开某个节点没做。
- 删节点时如果某个节点文件正好被杀毒软件或同步盘占住、改名失败，节点会从画布上消失但撤销找不回来。这是以前就有的写法，要机器上正好碰上文件被占住才会出现。

### 复查

修完以后又派了两个审查，一个看服务端和测试，一个看前端，一共报了 13 条，另有 2 条拿不准的。修了 12 条。

会丢数据的两条：

- **删画布时正好有图在往槽位里放**：处理大图要一秒左右，写图时会在原处重新建出画布文件夹，撤销恢复不了。上一轮只改了写节点文件那一处；现在放图、新建节点、岔出往画布文件夹里写时都不再顺手建文件夹，画布已经删了就报「找不到这个画布」（`packages/server/src/store/images.ts`、`packages/server/src/store/canvases.ts`）。用复查写的复现脚本连跑 3 遍，都能正常撤销。
- **失败的回复下面接着聊过几句，再点它的「重试」或切到别的版本**，后面那段对话在界面上就切不回去了。这是上一轮「重试不算新版本」带出来的。改成失败以后下面接着聊过的，照样算一个版本（`packages/client/src/canvas/Thread.tsx`）。

功能出错的两条：

- 生成中删节点再撤销，回复少最后一截、没有「已叫停」。改成和删画布一样，先等回复存完再挪进回收站（`packages/server/src/routes/canvases.ts`）。复现脚本连跑 3 遍，撤销回来的回复和页面上收到的一样长。
- 从一句带图片引用的需求岔出时预填的草稿，还有以前存下的旧草稿，还是按编号存的：不打字就调槽位顺序，切回来指到别的图。改成输入框打开时就按图存一次（`packages/client/src/canvas/Dock.tsx`）。

小问题：

- 撤销、重做的请求还在路上时又做了新操作或换了画布，这一步照样进了重做栈；连点时长还会并进正在撤销的那一步。改成先挪栈再发请求，没做成再挪回来。
- 服务停了或正在重启时，切版本、改名、自动排整齐、换模型配置和系统提示词失败了还弹成功的提示，失败的操作还留在撤销栈里；拼图放进槽位失败时说成「槽位满了」。改成做成了才弹提示，没做成的从撤销栈里拿掉。
- 点的节点读不出来时，面板还是上一个节点，引用图片、资产库、拼图却按新点的节点走，点了没反应。改成选中退回面板上那个节点。
- 生成中在「手动改」里点「存成新版本」，正在写的回复会从面板上切走。改成提示先叫停或等它写完。
- 首次设置第 2 步保存已有的模型配置，会把它挪到列表最后，新节点默认用的模型跟着变了。改成原位替换。
- 上传清单里从电脑拖进来、又被处理过的图，说明写成「原文件在 ，不要传它」。没有原路径时不写后半句。
- 端到端用例：「重答」用例查的是整个标题行，行里本来就有「重答」按钮，永远通过，改成只查标签；提示条上的「撤销」只测了不该撤时不撤，补上马上点能撤。

没修的：

- 删画布那几毫秒里，另一个页面正好在这个画布上开始生成，那次不会被叫停，模型白调一次，撤销后多一条空回复。要两个页面几乎同时操作才会碰到。
- 删画布是整个文件夹改名，Windows 上如果刚写好的文件正被杀毒软件扫描，可能报错删不掉，再点一次就行。复查拿不准会不会碰到，没改。
- 从电脑里一次拖进好几张图、其中有已经在槽位里的：要先传上去算出内容才知道重复，槽位快满时重复的那张也占名额。要改就得先全传上去再截断，会多存几张用不上的图进画布文件夹。复查拿不准要不要改，没改。

## 和原型对比

两份离线对照页，双击就能打开，左边原型、右边现在，1440×900，暗色亮色都有：

- `web/compare/step1.html`：首次设置和设置页，11 个画面。
- `web/compare/step2.html`：首页、画布、面板和各个弹窗，20 个画面。每个画面上面写了和原型不一样的地方。

结论：结构和样式一致。不一样的都是演示数据（路径、时间、图片张数、卡片概述）、截图时停不到的状态（正在生成），以及上面「和方案不一样的地方」说的那几处。

1. 用 `npm start` 打开你自己的工作文件夹，照两份对照页把各个画面过一遍，暗色亮色都看看。
2. 端到端测试模拟不了的：系统窗口选文件夹（首次设置「选择…」、设置页「换一个文件夹…」、拼图「选别的文件夹…」）、「在资源管理器里打开 / 显示」、从资源管理器真的拖图进槽位、上千张图的资产库滚动加载、真模型的流式回复。

## 要你定的事

1. **岔出来的子节点卡片上显示星标**。星标是按节点整条对话算的，复制来的那几条里有打过星的，子节点卡片上也亮星。原型只在自己打星的节点上显示。要不要改成只算这个节点自己的消息？
2. **从你的某句话岔出时，新节点槽位带哪一套图**。开发方案 5.3 写的是取上一条消息的；需求第 6 条写的是「从哪条消息 fork，新节点就带上那时候的图」。现在照开发方案做，如果这句话发出前改过槽位，岔出后输入框里的 `<Picture N>` 会指到别的图。
3. **服务端不检查请求是从哪个网址来的**。只监听本机挡不住这种情况：你开着程序时打开一个恶意网页，对方能借浏览器调这里的接口，比如把某套模型配置的接口地址改成他的，再点测试连接，服务端就会带着你的密钥去请求他。加一个检查就能挡住：请求里写的网址不是 127.0.0.1 或 localhost 的，一律拒绝。这是以前就有的，要不要加？
