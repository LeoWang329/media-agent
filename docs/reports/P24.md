# P24 局部重绘（拖框 + 涂抹）报告

「放一张图进去，指定改哪儿」的后一半：**圈定一块，只改这一块，别的一个像素不动**。用户要的是「不用涂抹」，接着说「同时也支持涂抹」，所以两个工具都做了，同一个窗口里切换、能叠加。规则在 `docs/dev-plan.md` 5.38，怎么定下来的见 `docs/plan-image-edit.md`。

## 做了什么

### P24a 掩码编辑器

- **入口**：大图窗口「做四视图」旁边加「局部重绘」。**Krea2 出的图不给这个按钮**（照「做四视图」的规矩，局部重绘走的是内置 SDXL 流程），服务端也拦（`Krea2 这期不支持局部重绘`）。
- **怎么画**：左边大图换成掩码编辑器（工具栏 + 原图画布），右边是「这块画成什么 / 额外的负面词 / 重绘强度 / 取消 / 开始重绘」。
  - **拖框**：按住拖出一个矩形，**在框里按住能拖动、拉四个角能缩放**；框描了一圈白色虚线，压在什么颜色的图上都看得见。
  - **涂抹 / 擦**：笔刷粗细可调（按原图像素算，默认短边的 5%），光标跟着一个圈；擦是把画过的挖掉。
  - **两个叠加**：框先画，笔迹按先后盖在框上面。
  - **撤销**（最近 20 步）/ **清空**。
- **画布按原图像素建**，显示时缩到框里，指针位置按显示框和画布实际尺寸的比换算，所以导出的就是原图尺寸的 PNG，不用二次缩放。
- **导出**：先单独画一张「哪里要重画」的掩码（白 = 重画，擦的笔迹是 `destination-out` 挖掉），再把它从原图上 `destination-out` 挖掉 → **要重画的地方 alpha=0、颜色照留、别处 alpha=255**，尺寸就是原图的。擦的笔迹在掩码里是「挖掉」，在这里才不会反过来把原图挖穿。
- **原型**：`web/prototype/image-mask.html`（首页原型列表第 08 条），和真界面同一套画法，浏览器直接点开就能拖框、涂、擦、撤销、清空。

### P24b 服务端、流程、mock

- **接口**：`POST /canvases/:canvasId/nodes/:nodeId/messages/:messageId/images/:jobId/:index/inpaint`，收 `{ mask（base64 PNG）、positive、negative、denoise }`。掩码认一下 PNG 文件头，不是就 400「掩码要是 base64 的 PNG」；强度不在 0 到 1 之间也 400。
- **掩码落盘**：存进 `image-temp/当天/`，名字 `HHmmss-mask.png`，路径记进这一组的 `params.inpaint.mask`。所以「已清理」那套逻辑自动适用，缺文件时报「这张图的掩码文件找不到了」。
- **流程照实例上的 `E05-局部重绘-手绘遮罩SDXL`**（`inpaintGraph`，另开一条，不塞进 `builtinGraph`）：
  `LoadImage`（槽 0 IMAGE、槽 1 MASK，掩码就是那张 PNG 的 alpha 通道）→ `InpaintCropImproved` → `InpaintModelConditioning`（`noise_mask=true`）→ `KSampler` → `VAEDecode` → `InpaintStitchImproved` → `PreviewImage`。
  底图和掩码同一张 PNG、同源，天然像素对齐，不用 `LoadImageMask`。
- **`InpaintCropImproved` 的参数照 E05**：25 个必填项全给。动过默认值的三处是 `mask_expand_pixels` 0→8、`output_target_width/height` 512→1024，另加 `context_from_mask_extend_factor` 1.2（裁的时候在掩码外多留 20% 上下文）、`mask_blend_pixels` 32、`output_resize_to_target_size` true、`output_padding` `'32'`、`device_mode` `cpu (compatible)`。参数表是照真机的 `object_info` 抄的（`output_padding` 是字符串枚举，可不是数）。
- **参数怎么拼**：底模、LoRA、步数、采样器、尺寸这些照原图那组记的（原图是导入的工作流出的，就用节点现在的出图设置）；正面、负面填了就按普通出图拼固定开头和默认负面词，**空着就用原图那组的**；种子随机一个。
- **一组记着从哪来**：`kind` 是 `inpaint`，`source` 指向原图那一组，「同样参数再来」「只换种子再来」重新上传存下的那张 PNG（按内容算名字，还是同一个名字），**不用再涂**；再来时 `source` 照旧指向最原始那张，和「补做」一样。
- **缺插件**：要装 `ComfyUI-Inpaint-CropAndStitch`，缺了照 5.18 说缺哪个节点、装哪个插件，一张都不发。
- **假 ComfyUI**：补上 `InpaintCropImproved`（出 STITCHER + IMAGE + MASK）、`InpaintModelConditioning`、`InpaintStitchImproved`，参数照真机那台写；`LoadImage` 本来就出 `['IMAGE','MASK']`，alpha 掩码那条路天然支持。

### 顺手修的一处（不在计划里）

`tests/e2e/env.ts` 的 mock 端口原来是写死的 3798/3799，`playwright.config.ts` 对这两个是 `reuseExistingServer: true`，所以**主机上已经有一套 dev 时，e2e 会复用那套旧进程，测的还是旧代码**（改了 mock 也看不出来，静默假绿）。现在这两个端口（加上 mock 的 SSH 端口）能从环境变量覆盖：

```powershell
$env:E2E_MOCK_COMFY_PORT='3898'; $env:E2E_MOCK_LLM_PORT='3899'; $env:E2E_MOCK_COMFY_SSH_PORT='3897'
npm run test:e2e
```

默认值没变，`npm run dev` 和 `npm run test:e2e` 的行为跟原来一样。

## 和计划不一样的地方

- **计划说掩码 PNG 走「和出图一样的临时文件夹」**，照做了，所以设置页「出的图」里那些按天分的子文件夹会把这几个掩码文件也算进张数。名字带 `-mask`，能认出来。要不要单独放一个文件夹，等用户看过再说。
- **计划里的单测「掩码合成」落在 e2e 里**：画布合成只能在真浏览器里跑（仓库里没有 jsdom 环境，client 也没进 vitest 的项目列表）。e2e 里是**把服务端落盘的那张 PNG 拿 `sharp` 逐像素读出来**验的：原图尺寸、框里 alpha=0、别处 255。纯逻辑那部分（流程拼接、参数）在 `packages/shared` 的单测里。
- **框只有一个**：同一时刻就一个矩形，能拖能拉角；想要第二个框就再拖一个（前一个被替换）。计划里没写多个框。
- **顺手修了 e2e 端口**（见上），计划里只把它列成「以后可以修」。

## 真机验证（P24c，出图那台，RTX 5090，ComfyUI 0.37.0）

脚本在 `outputs/real/`（`serve.ts` 起一个用临时配置和工作文件夹的本机服务、`verify.mjs` 跑 A/B、`probe.mjs` 出事时读那台的 `/history`）。

1. IL 出一张 832×1216（28 步、euler_ancestral、cfg 5，**15 秒**）。
2. 掩码：**原图照留，只把中间偏上一块 333×365 的透明度改成 0**（模拟拖框涂出来的那张 PNG），POST 到 `/inpaint`，正面 `1girl, solo, red leather jacket, smile, upper body`，强度 0.85。
3. **15 秒出完，尺寸 832×1216 没变**，`kind` 是 `inpaint`，`params.inpaint.mask` 是 `image-temp/2026-10-10/141516-mask.png`。
4. **遮罩外 827 927 个像素（离掩码 40 像素以外的全部），动过的 0 个，最大差 0** —— 逐字节和原图一样。掩码里那块重画成了红色皮衣领子。
5. 那台 `/history` 里读回来的 prompt 和计划里的 E05 接线一致：`LoadImage`（`mask` 接 `['5',1]`，就是 alpha 通道）→ `InpaintCropImproved`（24 个参数照 E05）→ `InpaintModelConditioning`（`noise_mask` true）→ `KSampler`（denoise 0.85）→ `VAEDecode` → `InpaintStitchImproved`（`stitcher` 接 `['6',0]`）→ `PreviewImage`。
6. **`output_target_width/height = 1024` 和 `mask_expand_pixels = 8` 这两个数不用改**：832×1216 上跑出来一次成功，接缝处只有一块硬边（因为测试用的掩码是硬边矩形、而且灰大衣整块换成了红皮衣，色差本来就大），没糊、没错位。

图片：`outputs/p23-p24-real/B1-原图.png`、`B2-重绘后.png`。
