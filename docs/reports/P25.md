# P25 图像编辑节点 · E1（节点模型）

「图像编辑」节点的第一步。规则在 [dev-plan.md](../dev-plan.md) 5.39，怎么定的看 [plan-image-edit-node.md](../plan-image-edit-node.md)（计划）和 [plan-image-edit-node-layout.md](../plan-image-edit-node-layout.md)（界面草图 + 能点的原型 `web/prototype/image-edit-node.html`）。

用户原话：「我需要额外有一个节点，图像编辑的界面。我可以打开一张图或多张图，然后有编辑的各类选项。有的节点编辑我还想让模型参与帮忙写提示词。」后面又逐条定了：功能做成下拉、每个功能一套自己的系统提示词而且能选、模型不许连着把功能也定了、第一轮所有功能都做、无审查当默认。

**E1 只做节点模型**：让第三种节点能建出来、能认自己的系统提示词、卡片和设置页对得上。面板里的编辑栏（功能下拉 / 图 / 提示词 / 开始）是 E2。

## 做了什么

### E1a 类型：`NodeKind` 独立出来，加 `'edit'`

- 以前 `NodeKind = PromptMeta['use']`（两者是同一个类型），现在各写各的：`NodeKind = 'video' | 'image' | 'edit'`，`PromptMeta['use']` 也是这三个，但不再互为别名，以后各自能走各自的。
- `PromptMeta` 多一个 `fn`：编辑提示词管的是哪个功能（指令编辑 / 换装 / 局部重绘 / 转真人），别的用途是 `null`。
- `PromptInfo` 跟着加 `fn`（设置页和节点下拉都要用）。
- `FormatRequirements` 加 `edit`，`NodeSummary` 加 `kind`（画布卡片按它分颜色、写标）。
- 见 `packages/shared/src/types.ts`。

### E1b 说明段：认「用途: 编辑」和「功能:」

- `parsePromptMeta` 现在把「用途」映射成 `生图 → image`、`编辑 → edit`、`视频 / 其他 → video`；顺手读「功能:」，没有是 `null`。
- 冒号中英文都认（跟原来一样）；没有说明段的还是视频提示词。
- 见 `packages/shared/src/promptMeta.ts`。

### E1c 四份编辑提示词进自带列表

- 新增 `docs/prompts/edit.md`（指令编辑）、`edit-outfit.md`（换装）、`edit-inpaint.md`（局部重绘）、`edit-real.md`（转真人），说明段都是 `用途: 编辑` + `功能: xxx`；共用的输出格式是 `format-requirement-edit.md`。
- `BUILTIN_PROMPTS` 从 8 套变 12 套；`FORMAT_REQUIREMENT_DOCS` 加 `edit`；`readFormatRequirements()` 多返回一份 `edit`。
- `defaultPromptFor(work, 'edit')` → 默认用 `edit`（指令编辑）那套；一套都没有返回 null。
- 见 `packages/server/src/store/prompts.ts`。

### E1d 建得出来、认得出

- **新建节点菜单**第三项「图像编辑节点」（图标 `wand`），建好就不能换，跟原来两种一个规矩。
- **卡片**：`.gn-kind` 标「编辑」（视频是「视频」、生图是「生图 · 系列」）；边框用新加的 `--edit` 青色，跟视频的灰、生图的紫分开。
- **设置页**第三组「写改图说明 · 图像编辑节点用」，每份带一个「编辑 · 功能名」标签；编辑器下面那句提示加了一份「（图像编辑那一份）。开头的「用途: 编辑」「功能: 换装」是程序认它的依据，别删」。
- **固定格式要求**那一页多一块「图像编辑节点的四套用这份」。
- 面板里的系统提示词下拉只列编辑那四套，选项写成 `edit · 指令编辑` 这样（生图那个位置原来是 `il · IL`）。
- 见 `Canvas.tsx`、`Graph.tsx`、`Settings.tsx`、`Drawer.tsx`、`design/app.css`、`design/image.css`。

### E1e 路由

- `POST /canvases/:id/nodes` 收 `kind: 'edit'`；一套编辑提示词都没有时报「设置里还没有图像编辑用的系统提示词」。
- `PATCH` 换系统提示词：编辑节点选生图/视频的报「图像编辑节点只能选图像编辑用的系统提示词」（三种节点各有一句话，抽成了 `KIND_PROMPT_ERROR`）。
- 老节点没记 `kind` 的照旧按现在用的系统提示词补：生图 → `image`、编辑 → `edit`、别的（包括提示词已经不在了的）→ `video`。
- `validate.nodeKind` 收三种，报错文案跟着改。
- 见 `packages/server/src/routes/canvases.ts`、`routes/validate.ts`、`store/canvases.ts`。

### E1f 顺手改的一处（不在计划里）

面板底部的参数区原来是 `use === 'image' ? 生图那套 : 视频那套`，加了编辑节点之后它会掉进"视频那套"、显示时长和比例 —— 那是错的。改成 `use === 'video' ? 视频那套 : 生图那套`，编辑节点先借用生图的尺寸张数，等 E2 的编辑栏替掉。代码里留了注释说明。

## 和计划不一样的地方

- **计划里 E1 写的是「`NodeKind` 加 `'edit'` 并和 `PromptMeta['use']` 解绑」**，落地时按「两边各写各的联合类型」做的（不是别名），这样以后哪边加成员都不会牵连另一边。
- **计划里 E1 没提 `NodeSummary` 要加 `kind`**。卡片要标「编辑」、要换边框色，前端拿不到 `kind` 只能靠 `image` 字段猜，所以加了。
- **设置页的提示词编辑器那句提示**原来只对生图说「用途: 生图」「底模: xxx」，现在编辑那套说「用途: 编辑」「功能: xxx」。
