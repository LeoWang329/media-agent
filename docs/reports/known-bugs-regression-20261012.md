## 修复内容

| 问题 | 根因与修复 | 验证 |
| --- | --- | --- |
| 局部重绘遮罩内黑块 | 编辑节点构造参数时漏存 `clipSkip`，退到了 1；补齐系列默认值，旧任务缺值时使用 IL/Pony 的默认 2。放大后的可选面部重绘也补齐同一参数 | 原输入对照、采样 latent 检查、服务端参数和旧任务测试、真实遮罩像素检查 |
| 删除失败后节点从画布消失 | 先移除布局、再移动文件，中途失败没有回滚。改为先准备回收站记录、移动所有文件，再移除布局；失败把已移动文件放回。复用已有 Windows 短暂占用重试 | 注入第二个文件 EIO，确认父子节点和回复保留；注入 EBUSY，确认删除及撤销成功 |
| 删除期间另一页面又开始生成 | 停止旧任务后，删除落盘期间仍能启动新的回复 | 删除全过程阻止同一画布/节点的新回复；持住实际 rename 验证返回 409，撤销后可再次生成 |
| 重复图片占用最后一个空位 | 上传前就按文件数截断，尚不知道文件内容重复 | 上传去重后只让新增图占空位；浏览器验证 8 张已有图再传“重复图、新图”，最终 9 张且最后一张正确 |
| 手工转真人 JSON 双图反推使用单图指令 | 343 节点复制了 342 节点的正文及标题 | 改为当前双图指令，测试比对两份完整正文；应用内标准流程四组合已经真机通过，历史手工模型组合的四组合也在 2026-10-13 补测通过 |
| AutoDL 缺货只显示通用错误 | 未识别本次真实响应中的“算力规格暂无库存” | 补充资源不足识别，并用真实响应原文回归；保留余额不足的独立判断 |

此前“E05 接线本身有问题”和“LoadImage 总把透明 RGB 合成黑底”的诊断不成立。检查 H3 的节点实现及 latent：旧参数编码后的 latent 有限，采样结果出现 65,536 个 NaN；只把 `clipSkip` 改为 2，采样结果恢复有限数值。浏览器擦除掩码时会清零该区 RGB，原图与掩码分开上传仍有必要，但并不是本次持续黑块的根因。没有替换 inpaint 流程、VAE 或采样算法。
