## 局部重绘这个问题（要接着修的）

现象：掩码画好、图也出了、尺寸跟原图一样、遮罩外没动 —— 但**要重画的那一块是纯黑的**。

查到哪一步了：

1. **掩码本身是对的**：在那台上单独跑 `LoadImage → MaskToImage` 探针，白框正好落在抠掉的位置（ComfyUI 的 `LoadImage` 的 MASK 输出 = 1 − alpha）。
2. **原设计有个坑**：E05 那条图是「一张 PNG 同时当底图和掩码」（`LoadImage.Image` → `InpaintCropImproved.image`、`LoadImage.Mask` → `.mask`）。ComfyUI 的 `LoadImage` 会把 RGBA **按 alpha 合成到黑底**，所以 alpha=0 那块在底图里永远是黑的。把框里的 RGB 填成中灰再试，出来还是黑的 —— 说明是它合成的，不是我们文件的问题。
3. **改成「底图和掩码分两张传」也不行**：`inpaintGraph` 现在会生成两个 `LoadImage`（底图原样、掩码那张取 MASK 口），真机上跑出来**还是黑块**；而且换 seed、把 denoise 从 0.85 调到 1，出图**逐字节一样** —— 说明生成结果根本没落到那块上。
4. 结论：**问题在 E05 这条流程本身**，不在我们传的东西。`docs/reports/P24.md` 当时只验了「遮罩外 827927 个像素一个都没动」，**没有验「遮罩里画成了什么」**，所以这个问题一直没暴露。
5. 下一步（没做）：接着查 `InpaintCropImproved` / `InpaintStitchImproved` 的出入参（尤其 `preresize` / `output_target_width|height` 和 stitch 那份 mask 的语义），或者干脆换一条 inpaint 流程（比如 SDXL 官方的 `VAEEncodeForInpaint` 那条）。

**界面照旧能用**（画掩码、参数、开始、出图挂在框下），但**在修好之前不要拿它当能干活的**。

## 集成时修掉的几个东西（都是收尾时发现的）

1. **`startEdit` 读的是「改之前」的节点**：先把节点读出来算好设置，再 `await patchesSaved()` —— 清空那句话之后马上点开始，发出去的还是旧那句。改成存完再读一次。
2. **`POST /edit` 只带 `{fn}` 时会把节点的设置换回默认值**（E4 时修的）—— 这个坑在编辑节点上被真机抓到过一次。
3. **`editRequestOf` 里硬编码了四个功能名**：加深度的功能时会直接 400。改成照 `EDIT_FNS` 认。
4. **插件名照实机核过**：`llama_cpp_*` 是 `llama-cpp_vllm`、`ColorCorrect` 来自 `comfyui-art-venture`、`FluxKontextMultiReferenceLatentMethod` 和 `ImageScaleToTotalPixels` 是 ComfyUI 本体；深度那三个控制节点是 `comfyui-krea2-controlnet`、`DepthAnythingV2Preprocessor` 是 `comfyui_controlnet_aux`。
5. **几处测试的断言过期**（都是新功能改了菜单/清单/文案导致的）：`11-images` 的 LoRA 清单、`23` 的菜单名和「尺寸」那句、`24` 的四视图正面词、`23` 那条「没选图时按住」拿 `_last-prompts` 判空（假 ComfyUI 的历史是整轮共用的，改成比前后条数）。
